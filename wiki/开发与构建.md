# 开发与构建

## 一、技术栈

| 项 | 值 |
|----|-----|
| 开发框架 | Vue 3（`^3.5`）+ Vite（`^8`）+ `@vitejs/plugin-vue` |
| 桌面封装 | Tauri 2（`@tauri-apps/cli` + Rust） |
| 运行时依赖 | vue、dompurify、highlight.js、mammoth、markdown-it、pdfjs-dist |
| 打包形态 | **iife 单 chunk**，零依赖，双击 `dist/index.html` 即可运行 |

## 二、目录结构

```
src/                  ← Vite root
├── index.html        ← 入口（Vue 挂载点 #app）
├── main.js           ← 样式引入 + createApp + AI/Markdown 依赖挂载
├── App.vue           ← 壳组件（import.meta.glob('?raw') 读取业务 JS → 间接 eval）
├── styles/           ← variables / layout / components
├── core/             ← 数据 / 工具 / UI / AI / 路由（15 个模块）
├── views/            ← 12 个业务视图
└── public/           ← images / vendor（原样复制到 dist/）
docs/                 ← 操作手册 / API / flows / version
wiki/                 ← GitHub Wiki 页面源
scripts/              ← 构建 / 版本 / 文档脚本
src-tauri/            ← Rust 源码 + tauri.conf.json（frontendDist=../dist）
dist/                 ← 构建产物
```

## 三、关键构建约束（不可移除）

`vite.config.js` 中三项配置必须保持，否则 `file://` 双击运行会失败：

| 配置 | 作用 |
|------|------|
| `base: './'` | 相对路径资源引用 |
| `output.format: 'iife'` | 非 module 打包，避免 CORS |
| `demoteModuleScripts()` | 将 `<script type="module">` 降级为 `<script defer>`，file:// 下可加载 |

另有 `injectSwVersion` 插件写盘后替换 `sw.js` 缓存名；`define` 注入 `__APP_VERSION__`。

## 四、常用命令

```bash
npm install
npm run dev           # Vite 开发服务器（localhost:1421）
npm run vite:build    # 构建零依赖产物到 dist/
npm run build         # vite + tauri + dmg 全流程
npm run tauri:dev     # 桌面版开发
npm run tauri:build   # 桌面版打包（走 scripts/with-updater-key.mjs）
npm run version:check # 校验版本号多处一致
npm run version:set   # 统一刷新版本号（核心三处 + 派生项）
node scripts/gen-coverage.mjs  # 重新生成 docs/COVERAGE.md
```

## 五、版本号规则

- **单一来源**：`package.json` 的 `version`，构建时注入 `__APP_VERSION__`
- **核心同步三处**：`package.json` / `src-tauri/tauri.conf.json` / `AGENTS.md` 基准版本
- **派生同步项**：`package-lock.json`、`src-tauri/Cargo.toml`、`src/core/store.js` 兜底值、`dist/sw.js` 缓存名
- **禁止推进版本号的场景**：同类问题多轮跟进、同日同模块追加修复、用户明确不改、仅文档更新、纯 CSS/文案/去抖打磨
- 不推进版本号也必须追加 `docs/version/RELEASE-v1.0.md` 日志（只增不改）

## 六、业务层约定

- `src/core/` 与 `src/views/` 下业务 JS 以**间接 eval 全局执行**，保持 `window.*` 全局语义，**不得轻易改写为 ES module import/export**
- 加载顺序：`seed → utils → ui → store → exporter → ai → help-knowledge → ai-tools → ai-files → kb → validators → views/* → router → app`
- 校验统一放 `validators.js`（视图层与 AI 工具层共用）
- HTML 拼接中用户数据必须经 `escHtml()` / `escAttr()` 转义
- 搜索框**回车触发**，禁止 `oninput` 实时搜索（中文输入法冲突）
- 高频事件必须防抖 / 节流

## 七、文档维护

| 文档 | 何时更新 |
|------|---------|
| `docs/操作手册.md` | 用户可见功能变更 |
| `docs/API.md` | 数据模型 / 全局函数 / Tauri 命令变更 |
| `docs/flows/*.md` | 模块流程或关键函数变更 |
| `docs/COVERAGE.md` | `node scripts/gen-coverage.mjs` 重新扫描 |
| `docs/version/RELEASE-v1.0.md` | 每次迭代（含不推进版本号的修复） |
| `wiki/*.md` | 随上述文档同步刷新 |
