# 寻货与分配

一个产品规格可由**多个供应商分别供货**（单个供应商库存常不足以满足需求），系统按分配量自动汇总寻源进度。

## 一、两种寻货方式

### 方式一：从价格库匹配

1. 在产品明细行点击「寻货」
2. 弹窗顶部显示：需求量 / 已分配量 / 剩余量 / 销售价 / 寻源状态
3. 系统列出价格库中匹配的报价（规则见下）
4. 每条显示：供应商、单价、单位利润、联系人
5. 填写「分配数量」（默认填入剩余量）→ 点击「+ 添加」

**匹配规则（v1.0.54 起）**

| 场景 | 规则 |
|------|------|
| 行与报价都有 SKU | 必须**完全一致**才命中 |
| 报价无 SKU | 仅当订单行有属性可核验且一致时兜底显示 |
| 订单行无 SKU | 沿用属性匹配（兼容老数据） |

### 方式二：手动录入

在弹窗下方填写供应商、采购单价、分配数量、库存/交期备注 → 「保存并添加」。

**系统自动处理**：新供应商自动创建关联单位（角色=供应商，评级=新客）→ 自动将报价写入价格库 → 加入分配列表。

## 二、多供应商分配校验（v1.0.56 起）

- 弹窗顶部**实时**显示：`已勾选 N 家 · 分配合计 X / 剩余 Y`（超量标红）
- 新勾选供应商的默认分配量**自动收窄**为「剩余 − 其他已勾选行合计」
- 提交时若合计超量 → toast 提示且**不关闭弹窗**，可就地调整

## 三、寻源状态

| 状态 | 条件 | 标签颜色 |
|------|------|----------|
| 待寻源 | 无任何供应商分配 | 红色 |
| 部分寻源 | 分配总量 < 需求量 | 黄色 |
| 已确认 | 分配总量 ≥ 需求量 | 绿色 |

每个产品明细行下方显示**分配进度条**：绿色=满量，黄色=部分，空白=未寻货。

## 四、开始寻货的前置校验

> v1.0.47 起：**意向价不再拦截**（0 / 空 / 未填均放行），仅校验 SKU、名称、规格。

校验收口在共享函数 `validateStartSourcing(order)`，视图按钮与 AI 工具 `flow_order_status` **共用同一套规则**。

## 五、管理已选供应商

- 在寻货弹窗「已选供应商」区域点击 × 移除某个分配
- 移除后自动重新计算寻源状态与进度条

## 六、供应商报价批量导入（v1.0.57 重构）

入口：寻货弹窗 / 产品行的「批量导入」。

**列结构（7 列）**

```
序号 | SKU（必填）| 数量（千支，必填>0）| 意向价 | 报价（元/千支）| 供应商 | 规格（可选）
```

规则：

- 按 `it.sku === r.sku` **精确相等**匹配订单产品行（不再按名称猜测）
- SKU 缺失的行判为无效并跳过
- 意向价 > 0 时回填订单产品行的 `salePrice`
- 报价写入寻货结果 `option.price`，数量写入 `option.allocQty`（**受剩余量限制**）
- 同一 SKU 多行不同供应商 → 自然生成**多条寻货结果**（多供应商分配）
- 供应商列按名称匹配已有单位（roles 含「供应商」）或自动新建
- 去重 key：`sku | supplierName | qty | price`

示例文件：`docs/导入数据Demo.xlsx`「供应商报价」sheet。

## 七、数据流

```
寻货操作（编辑模式）
addMatchSupplier / manualSupplier / removeOption
    → _fItems 更新 → persistOrderItems() → DB.orders → saveDB()

寻货操作（详情模式）
sourceItemFromDetail → sourceItem 弹窗 → 上述三函数
    → persistSourcingFromDetail() → DB.orders → saveDB()
```

编辑模式下产品明细的添加 / 修改 / 删除 / 寻货分配**均自动写库**，无需手动「保存订单」（该按钮只保存表单元信息）。

返回：[采购订单](采购订单.md)
