# 对账结算

分为「收款记录」（向采购商收取）和「付款记录」（向供应商支付）两个维度，基于**签约完成 / 送货中 / 完成**状态的订单自动计算应收 / 应付。

## 一、Tab 结构

| Tab | 路由 key | 说明 |
|-----|---------|------|
| 收款记录 | `settle-receipt` | 对采购商的应收 |
| 付款记录 | `settle-payment` | 对供应商的应付 |

每个 Tab 内再分「未结 / 已结」子 Tab（快捷键 `⌥ + ←` / `⌥ + →` 切换）。

## 二、新增结算记录

入口：`openNewSettlement(presetUnitId, type)`

1. 选择单位（采购商 → 收款；供应商 → 付款）
2. 系统自动列出该单位名下处于聚合状态的订单
3. 勾选参与本次结算的订单
4. 金额可自动汇总，也可手工调整
5. 填写结算日期、方式、备注 → 提交

## 三、结算明细

`openSettleDetail(unitId, tabType)` 抽屉展示：

- 该单位的应收 / 应付汇总
- 关联订单逐行明细（金额、已结、未结）
- **「未定价」标记**（v1.0.56 起）：订单有产品行但应收为 0（意向价未填）时标注，hover 有说明
- 相关发票记录

## 四、与订单状态的联动（v1.0.56 起）

订单从聚合状态集（签约完成 / 送货中 / 完成）**转出**且存在关联结算记录时，会弹确认窗：

> 已关联 N 条结算记录（合计 X 元），转换后不再计入聚合（记录保留，恢复状态后重新计入）

这样避免「订单转异常后应收应付凭空消失，而收付款记录还在」的对账错位。

## 五、删除结算

- 删除确认弹窗可勾选「**同时删除关联的 N 条发票记录**」（级联软删进回收站）
- 不勾选时，关联发票会被标记 `orphan`，在 [发票管理](发票管理.md) 列表显示「**来源已删**」标签；悬空消除后标签自动摘除

## 六、数据结构

```javascript
DB.settlements = [{
  id:'S1', type:'receipt',        // receipt 收款 / payment 付款
  unitId:'U101', amount:12000,
  date:'2026-08-20', method:'转账',
  orders:['PO260811-001'],        // 关联订单
  remark:''
}];
```

## 七、常见问题

**Q：为什么某张订单没出现在结算里？**
结算只聚合「签约完成 / 送货中 / 完成」三种状态的订单。请检查订单状态。

**Q：应收显示为 0 并标注「未定价」？**
v1.0.47 起意向价允许为 0 / 空，按 0 计入是合法的，系统用「未定价」标签提示核对。补填意向价后标签消失。

**Q：删除结算后发票还在吗？**
默认保留并标记「来源已删」；勾选级联删除则一并软删（可在回收站恢复）。
