# 版本迭代日志

> 本目录专门存储紧固件贸易工作台每次升级迭代的发布日志。
> 命名规则：`RELEASE-v{主版本}.md`（如 v1.0.x → RELEASE-v1.0.md，v1.1.x → RELEASE-v1.1.md）
>
> **版本纪律（与 AGENTS.md §0 严格对齐）**：
> - 版本号末位仅在「不同类新功能 / 不同根因新修复 + 用户明确允许」时 +1
> - **绝对禁止推进版本号的场景**：同一问题多轮往返跟进、同日同模块追加修复、用户明确要求不改版本号、仅文档更新、纯 CSS/文案/去抖体验打磨
> - 要求版本回退时，核心三处（`package.json` / `src-tauri/tauri.conf.json` / `AGENTS.md` 基准版本）必须同时回退到用户指定值；`package-lock.json`、`src-tauri/Cargo.toml`、`src/core/store.js` 兜底值为派生同步项，随 `npm run version:set` 一并刷新
> - **即使不推进版本号，也必须记录发布日志**：追加到主版本文件中当前版本号对应分节内，注明日期；**同一版本号只保留一个分节**，后续批次整合进该分节（不新开同版本号分节）；历史日志只增不改

## 约定

- **按主版本一个文件**：`RELEASE-v{主版本}.md`；仅版本号推进时在文件顶部新开分节（最新在前），**同一版本号的多批迭代整合进该版本号唯一分节**，不拆成多个同版本号分节
- **发布前**：在对应主版本文件追加该次版本分节；版本号同步递增仅当 AGENTS.md §0 允许的唯一场景
- **发布后**：分节状态标记 ✅ 已发布；`version` 目录内已发布内容只增不改（历史日志不可篡改）
- 待发布内容先以 📝 待发布 状态记录，发布时更新状态与日期
- **去重整理（2026-08-28 起）**：同类问题多次修复的条目合并为一条，统一记述于最终修复版本；被合并的早期版本分节保留编号与合并指向（不删版本号、不重复正文）。当前最新基准版本 **v1.1.1**
