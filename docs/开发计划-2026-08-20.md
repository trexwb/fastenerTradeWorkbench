# 紧固件贸易工作台 · 开发计划（Roadmap）

> 版本：v2.0（2026-08-20 优化版）
> 当前应用版本：v1.2.0
> 定位：**离线单干版超简单 CRM + 个人贸易工作台**

---

## 1. 背景与定位

紧固件贸易工作台目前是一个纯原生 JS 的单页应用（SPA），已覆盖：

| 模块 | 现有能力 |
|---|---|
| 概览 | 首页汇总 |
| 关联单位 | 客户/供应商档案（联系人、电话、地址） |
| 属性管理 | 紧固件规格主数据 |
| BOM 管理 | 产品结构 |
| 签约管理 | 价格协议 |
| 采购订单 | 订单增删改查、明细、状态流转、Excel 导出（6 种状态专用模板） |
| 对账结算 | 收款/付款记录 |
| 发票管理 | 开票/收票记录 |
| 数据管理 | 导入/导出/同步 |

### 目标定位

- **离线优先**：双击 `index.html` 即可使用，无需 HTTP 服务器、无后端依赖
- **单干场景**：不引入团队/权限概念，一切功能围绕"一个人干完所有事"的提效与防漏
- **超简单 CRM**：不是管理工具，而是**个人生意管家**——把客户关系、供应商关系、订单流、资金流串成一条线

### 核心设计原则

1. **省时间优先**：高频操作（报价、录单、催款）必须最快路径，减少重复录入
2. **防漏兜底**：自动提醒代替人工记忆（催款、交期、跟进、验收）
3. **双面关系**：同时管好客户侧（应收/催款/跟进）和供应商侧（应付/交期/比价）
4. **看清钱收尾**：每笔生意从报价到收款全程利润可见
5. **一人能用**：所有信息一键可查、可复制到微信/邮件，不需要二次整理
6. **改动小、风险低**：优先复用现有模块数据，不引入新依赖
7. **渐进式**：三期推进，每期可独立使用

## 2. 总体规划（三期）

### Phase 1 🥇 省时间 + CRM 打基础

**目标**：日常重复劳动最快路径化，补上 CRM 基础能力，让一个人能像团队一样高效。

| # | 功能 | 说明 | 优化理由 |
|---|---|---|---|
| 1 | 报价中（订单内报价） | 采购订单进入「报价中」状态即报价单：选规格 → 自动匹配签约价/历史采购价 → 设利润率自动算售价 → 导出/打印报价单；客户确认后直接进入「签约完成」 | **个人单干核心痛点**：报价是最高频动作；报价不独立建表，就是订单的一个阶段 |
| 2 | 一键复制订单（含未成交/取消） | 任意历史订单复制为新订单，保留客户、规格、数量及供应商、报价（可按需手动删除），重新走寻货→报价流程 | **个人单干**：老客户返单、未成交需求换供应商重新询价 |
| 3 | 客户跟进记录 | 每个客户增加时间线：联系时间 / 沟通方式 / 内容 / 下次跟进日期 | **CRM 深挖**：关系维护是个人贸易的核心，好记性不如烂笔头 |
| 4 | 客户分级与标签 | 手动维护 A/B/C 分级（主力/备选/新客已对齐现有 rating 字段）与自定义标签 | **CRM 深挖**：精力有限，分级决定跟进频率和信用额度 |
| 5 | 常用模板与历史复用 | 同客户同产品一键复用上次价格/备注；按客户查历史报价 | **个人单干**：80% 的订单是老客户老产品，复用比新建快十倍 |
| 6 | 快捷通讯录 | 按角色（客户/供应商）快速检索联系人电话，点击复制或一键拨号 | **个人单干**：微信/电话沟通频繁，需要快速找到联系人电话 |
| 7 | 报价历史比价 | 同一规格查看所有供应商历史报价，一眼看穿底价 | **CRM 深挖**：贸易中间商赚差价，掌握供应商底价是核心能力 |

**依赖现有模块**：签约管理（价格基准）、采购订单（报价中状态承接报价）、关联单位（跟进挂载点）、属性管理（规格来源）。

### Phase 2 🥈 防漏 + 关系维护

**目标**：数据积累后启动自动提醒，防止漏款、漏交期、漏跟进，让客户关系不因忙而断。

| # | 功能 | 说明 | 优化理由 |
|---|---|---|---|
| 8 | 今日待办清单 | 首页聚合：今日待催款 / 待跟进 / 待验收 / 即将到交期，一项项打勾完成 | **个人单干核心**：一个人干所有事最怕忘，待办清单就是第二大脑 |
| 9 | 应收到期提醒 | 首页展示"X 天后应收 X 客户 X 元"，超期标红，点击可复制催款话术 | **个人单干**：催款是刚需，话术模板直接复制到微信 |
| 10 | 供应商交期提醒 | 已下单未交货的，接近交期自动提醒；超期标红 | **防漏**：供应商延迟直接影响对客户承诺，必须提前预警 |
| 11 | 跟进提醒 | 到期"下次跟进日期"的客户自动提醒，超 30 天未跟进标黄 | **CRM 深挖**：客户流失往往从"忘了跟进"开始 |
| 12 | 客户流失预警 | 超过 N 天无交易、无跟进的客户自动标黄，按分级排序 | **CRM 深挖**：主力客户流失损失最大，需主动预警而非被动发现 |
| 13 | 一键催款/催货 | 生成催款/催货话术模板（含订单号、金额、到期日），一键复制到剪贴板 | **个人单干**：催款催货话术不需要每次重新写，模板化省时间 |
| 14 | 到货验收记录 | 供应商发货到货后记录：实收数量 / 验收结果 / 异常备注 | **个人单干**：收货验货是中间商必做环节，验收异常要能追溯 |
| 15 | 库存预警 | 常用规格低于安全库存提醒补货（需先建库存台账） | **防漏**：常用规格缺货丢订单 |

### Phase 3 🥉 看清钱 + 客户分析

**目标**：基于完整数据提供决策支持，每笔生意赚多少、亏多少、谁值得维护一目了然。

| # | 功能 | 说明 | 优化理由 |
|---|---|---|---|
| 16 | 单笔利润即时核算 | 录单/报价时实时显示预估利润（售价 - 采购成本 - 费用），利润率低于阈值红色提醒 | **个人单干**：报价时不知道赚多少等于盲报，实时算价防亏本 |
| 17 | 订单利润核算 | 每单实际利润 = 应收金额 - 采购成本 - 运费/杂费 - 损耗 | **看清钱**：每单赚多少必须算清楚，不能凭感觉 |
| 18 | 资金流水看板 | 收付款汇总，按月/按客户/按供应商看收支明细，一眼看清明细 | **个人单干**：一个人要管好现金流，知道谁欠我、我欠谁 |
| 19 | 生意体检看板 | 当月销售额 / 回款率 / 平均毛利率 / 在途订单 / 库存占用一页看清 | **看清钱**：月度体检，趋势一目了然 |
| 20 | 客户画像统计 | 交易频次、累计金额、毛利率、回款周期、自动分级推荐 | **CRM 深挖**：知道哪些客户真正赚钱，精力分配有依据 |
| 21 | 供应商绩效评估 | 交期达成率、价格竞争力、质量退换记录，自动推荐最优供应商 | **CRM 深挖**：供应商好不好不能凭印象，数据说话 |
| 22 | 项目利润核算 | 按项目维度汇总多个订单的利润（一个项目可能分多批送货） | **个人单干**：贸易公司常按项目结算，需要看项目总盘而非单笔 |

## 4. 数据结构变更预览

以下新增字段挂载在现有 DB 结构上，不破坏已有数据：

### 4.1 客户跟进记录（新表 `DB.followUps`）

```js
DB.followUps = [
  {
    id: 'FU1',
    unitId: 'U1',           // 关联 units
    date: '2026-08-20',      // 联系日期
    method: '电话',           // 电话/微信/拜访/邮件
    content: '客户确认M8螺栓规格...',  // 沟通内容
    nextDate: '2026-08-25',  // 下次跟进日期
    orderId: 'PO260805-001', // 关联订单（可选）
    createdAt: '2026-08-20'
  }
]
```

### 4.2 报价单（不独立建表）

报价不独立建表，由采购订单的「报价中」状态承担。报价数据挂在订单 items 的已有字段上：

- `items[].salePrice`：意向价（报给采购商的初始价格，寻货前填写）
- `items[].quotePrice`：最终报价（寻货后生成的报价，报给采购商的最终价）
- `items[].costPrice`：采购成本（供应商报价，从分配结果汇总）
- `items[].options`：供应商分配列表（含 supplierId、price、qty）

订单进入「报价中」状态时，其本身即报价单，可导出/打印为报价单格式。整个订单生命周期中，报价相关字段随状态流转自然承载，无需额外建表。

### 4.3 验收记录（新表 `DB.receipts`）

```js
DB.receipts = [
  {
    id: 'RC1',
    orderId: 'PO260728-002',
    itemId: 'I3',
    supplierId: 'U5',
    receivedQty: 1500,       // 实收
    expectedQty: 1500,       // 应收
    result: '合格',           // 合格/部分合格/不合格
    remark: '',
    date: '2026-08-15',
    createdAt: '2026-08-15'
  }
]
```

### 4.4 待办事项（运行时聚合，不持久化）

从 followUps + settlements + orders + delivery 实时聚合，首页展示当日待办。

## 5. 关键约束（贯穿所有阶段）

- **技术栈**：纯原生 JS（全局函数式），无框架、无构建、无 npm 依赖（xlsx-js-style CDN 例外）
- **存储**：localStorage + IndexedDB + JSON 文件同步（沿用现有 File System Access 机制）
- **架构**：多文件 script 加载（js/views/*.js 每视图一个文件），新增模块遵循同构
- **入口**：`index.html` 双击打开即用
- **交互风格**：延续现有抽屉 + 弹窗 + 表格的极简风格
- **快捷键**：遵循 v2.0 三层结构（⌥ 导航 / ⌥⇧ 动作 / ⌘ 保存），新增功能若配快捷键需挂入说明弹窗
- **数据兼容**：新增字段使用 `ensureDBFields()` 迁移，不破坏已有数据

## 8. 报价管理并入采购订单 · 详细设计（2026-08-20 确认版）

> 结论：**报价不独立建表，不设「报价转订单」流程**。报价是采购订单生命周期中的一个阶段（「报价中」状态），订单即报价单。

### 8.1 状态机

```
创建 → 待确认 → 寻货中 → 报价中 → 签约完成 → 送货中 → 完成
                    ↑ 回退 │                    ↘ 异常
                    │      ├→ 未成交（报价发出后客户没下文）
                    │      └→ 取消（任意阶段可主动放弃）
```

| 状态 | 说明 | 可执行动作 |
|---|---|---|
| 待确认 | 临时/不确定的采购需求 | 录入产品、意向价；开始寻货；取消 |
| 寻货中 | 询价、比价、分配供应商 | 从价格库匹配供应商、手动分配、批量导入报价；完成寻货进入报价中；取消 |
| 报价中 | 即报价单（原待签约） | 生成/调整报价；回退到寻货中重新调价换供应商；确认签约；标记未成交；取消 |
| 签约完成 | 采购商已确认报价 | 供应商和报价**锁定不可改**；进入送货 |
| 未成交 | 报价后客户没下文 | 恢复为报价中继续跟；保留在列表可筛选 |
| 取消 | 主动放弃 | 不可恢复 |

### 8.2 核心规则

1. **报价回退**：报价中可回退到寻货中，重新分配供应商、调整价格，再回到报价中——报价有调整或供应商有变更时使用。
2. **签约锁定**：进入签约完成（报价确认）后，供应商分配（options）和报价（quotePrice）均不可修改；界面只读。
3. **不冻结快照**：不单独留存报价历史快照，订单明细即报价内容；单机替代 Excel，约束从简。
4. **未成交 vs 取消**：未成交=报价后客户没下文（有价值可复用）；取消=主动放弃（录错/不做了）。二者均不参与应收/利润/待办统计。
5. **一键复制**：任意状态订单（含未成交/取消）可复制为新订单，**保留**客户、规格、数量、供应商分配和报价（可按需手动删除），复制后为待确认状态，重新走寻货→报价流程。
6. **未成交恢复**：未成交订单一键恢复为报价中，保留已有报价继续跟同一客户。
