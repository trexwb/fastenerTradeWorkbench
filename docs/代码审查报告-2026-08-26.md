## 1. P1 严重问题（影响视觉正确性 / 数据安全）

### 1.1 五个 CSS 变量被引用但从未定义 —— 样式静默失效

`variables.css` 两个主题（default/cream）中均不存在以下变量，但代码中共 10+ 处引用。CSS 变量未定义时该属性回退为继承值/初始值，**不报错、不降级提示，直接失效**：

| 变量 | 引用位置 | 失效表现 |
|------|---------|---------|
| `--blue` | `utils.js:603`（combo「新建」提示项）、`dashboard.js` 两处「查看全部→」链接、`invoices.js`、`ai-chat.js` | 链接/提示回落为正文黑色，蓝色引导色不生效 |
| `--warn` | `store.js`（绑定文件夹安全提示）、`orders.js`（收货未完成提示列表） | 警示文案回落为普通色，弱化风险提示 |
| `--text` | `components.css:541` `.sg-toggle-btn:hover` | hover 变色失效 |
| `--fg-soft` | `layout.css` `.theme-tgl`（顶栏主题切换按钮） | 按钮文字色回落为继承色 |
| `--pri-bg` | `components.css` `.bs-step .bs-n`（批量导入步骤序号背景）、`layout.css` `.theme-tgl:hover` | 序号徽章/按钮 hover 背景透明 |

**修复建议（二选一）**：
- A（推荐）：在 `variables.css` 两个主题块各补 5 个变量定义（如 `--blue:var(--pri)`、`--warn:var(--amber)`、`--text:var(--ink)`、`--fg-soft:var(--gray)`、`--pri-bg:var(--pri-l)`），保持两主题各自协调；
- B：全局替换为现有语义变量（`--pri`/`--amber`/`--gray`/`--ink`/`--pri-l`）。

### 1.2 抽屉遮罩点击绕过「未保存确认」—— 脏数据可能无提示丢失

`src/core/ui.js:91`：

```js
overlay.onclick=safeCloseDrawer;   // 事件对象被当作 force 参数传入
```

`safeCloseDrawer(force)` 的第一参数被 `onclick` 自动注入的 **MouseEvent** 占据，事件对象恒为 truthy → `force||!_drawerDirty` 恒真 → **点击遮罩直接关闭抽屉，跳过未保存确认**。表单填写中误点遮罩即丢失全部输入（与「继续编辑/确认关闭」弹窗设计意图冲突）。

**修复**：改为 `overlay.onclick=function(){safeCloseDrawer();};`

### 1.3 `confirmModal` 消息体未转义 —— 存在存储型 XSS 路径

`src/core/ui.js:54` 将 `msg` 直接拼入 innerHTML（`'<p ...>'+msg+'</p>'`），而全项目其他输出点均有 `escHtml()` 纪律。调用方中至少两处 msg 含**用户可录入数据**：

- `prices.js` `batchDeletePrices()`：msg 拼入 `pName(p.unitId)`（单位名）与订单号；
- `prices.js` `delPrice()`：msg 拼入 `specLabel(p)`（规格文本）。

若单位名/规格中录入 `<img onerror=...>` 类内容，会在确认弹窗中执行。本地单机工具实际风险低，但违反安全规范「所有用户数据渲染前必须转义」。

**修复**：confirmModal 内部对 msg 做 `escHtml()`（注意 `batchDeletePrices` 的 msg 含 `\n`，需同时 `replace(/\n/g,'<br>')` 保住换行排版）。

## 2. P2 中等问题（主题一致性 / 规范 / 可维护性）

### 2.1 硬编码颜色 94 处（components.css）+ 视图层大量内联 hex

`components.css` 存在 94 处 `#xxxxxx` 字面量（sync-banner、表格斑马底、tooltip `#1e293b`、表单错误 `#dc2626` 等）；`data.js`、`units.js` 等视图内联样式亦大量 hex。后果：**cream 主题下出现 default 主题的色斑**，两套主题未完全对齐。典型如：

- `utils.js:589` combo 下拉 `background:#fff`、`utils.js:621` 激活项 `#eff6ff` —— cream 主题（bg `#fbf9f4`）下白面板突兀；
- `.bs-step`、storage 状态卡（data.js）整体走硬编码色。

**建议**：按「状态色」语义补齐变量（`--info/-l`、`--err-l`、`--tip-bg` 等），逐步替换高频区域；combo 下拉至少 `background:var(--card)`。

### 2.2 死选择器：`.shortcuts-modal .modal .mb`

`components.css:532`。实际 DOM 是 `<div class="modal shortcuts-modal">`（keyboard.js:67），`.shortcuts-modal` 与 `.modal` 在**同一元素**上，后代选择器永不匹配 → 该 padding 规则为死代码。应为 `.shortcuts-modal .mb`。

### 2.3 行渲染代码重复（DRY 违规）

| 位置 | 重复内容 |
|------|---------|
| `prices.js` 16–28 行 vs 103–115 行 | `viewPrices()` 与 `refreshPricesTable()` 的表格行 HTML **逐字相同** |
| `store.js` `ensureDBFields()` vs `initApp()` | 字段回填逻辑两份 |
| `units.js` `viewUnits()` vs `refreshUnitList()` | 单位行渲染两份 |
| `bom.js` `parseBOMBatch()` vs `removeBatchRow()` | 预览表 HTML 两份 |

改行模板时极易漏改一处。建议抽取 `priceRowHTML(p)` 等行模板函数，两处共用。

### 2.4 `var` 残留 125 处（规范：禁止 var）

分布：`exporter.js` 94、`utils.js` 16、`units.js` 6、`bom.js` 4、`prices.js` 3、`router.js` 2。`orders.js`（1787 行）、`keyboard.js`、`ai-chat.js`、`data.js`、`specs.js` 已全部 const/let ✅。建议随功能改动顺手清理，不必专项重构（符合「最小改动」原则）。

### 2.5 跨文件隐藏依赖 + 硬编码 z-index

- `utils.js` `restorePriceDraft()` 调用 `units.js` 的 `contactOpts()` —— 工具层反向依赖视图层，加载顺序敏感（当前靠 App.vue glob 顺序保证）；
- `utils.js:589` combo 下拉 `z-index:200` 硬编码，而 `variables.css` 已定义 `--z-combo:40/--z-combo-over:60`，绕过了集中管理层。

### 2.6 `confirmModal` 实参 6 个、形参 5 个

`ui.js:74` 传入第 6 参 `'warning'`（疑似想传图标/风格），函数签名无此参数，被静默丢弃。要么删除，要么补实现。

## 3. P3 轻微问题（可择机优化）

1. **`orders.js` 单文件 1787 行、40+ 函数**：建议按「列表 / 详情 / 编辑 / 寻源报价」拆分（注意保持 window.* 全局语义，与现有 eval 加载兼容）。
2. **`newPrice()`/`editPrice()` 用 `setTimeout(...,50/100)` 等 DOM 就绪后绑 combo**：时序脆弱，极端慢机上可能绑定失败；建议抽屉挂载后同步回调代替定时器。
3. **`specs.js` CSV 导出未做引号转义**：值含英文逗号/引号会错列（导入 Excel 才暴露）。
4. **`keyboard.js` Enter 兜底用正则反向解析 `onclick` 字符串取函数名**：脆弱的元编程，函数改名即失效；建议搜索框统一 `data-search-fn` 属性。
5. **`ai-chat.js` markdown 表格仅按行渲染为 `div.ai-table-line`**：不是真表格，列宽不对齐，多列表格可读性差。
6. **`ai.js` 浏览器版 API Key 存 localStorage**：违反「敏感信息不入 localStorage」规范；但本工具为单机 file:// 场景且 Tauri 版已走本机目录存储，属可接受折衷——建议在代码注释中已声明的基础上，于操作手册补一句风险说明。

## 4. 符合规范的亮点（无需改动）

- **架构约束 100% 合规**：`base:'./'` + iife + demoteModuleScripts 均在位；xlsx-js-style 豁免链（本地 vendor → CDN 兜底 → cpexcel 预载）完整实现，未混入社区版 xlsx；
- **escHtml/escAttr 纪律**：全项目约 300+ 输出点仅 1.3 节所述缺口，覆盖率很高；
- **z-index 集中管理**（variables.css 10 层体系）思路正确，仅 combo 一处逃逸；
- **UX 设计**：表单草稿自动保存/恢复、脏抽屉关闭确认（除 1.2 缺陷外）、删除前引用检查（报价被订单寻源引用时警告）、导入数据完整性预检、快捷键三层体系 + 输入框自动禁用，体验完整度高；
- **键盘可达性**：combo 有 ARIA role/aria-label，按钮有 title，stat-card 有 role="button"+tabindex；
- **`prefers-reduced-motion` 适配**、大屏三档断点（1600/1920/2560）均已覆盖。
