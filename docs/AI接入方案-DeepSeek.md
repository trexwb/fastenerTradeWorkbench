# 紧固件贸易工作台 · DeepSeek AI 接入方案

> 版本：v2.1（2026-08-23 修订版：安全代理、V4 模型与流式 IPC 方案）
> 目标应用版本：v1.0.0+（AI 功能作为独立增强模块）
> 定位：**离线优先，AI 增强**——核心功能完全离线可用，AI 能力按需开启
>
> **双形态交付**（v2.0 起）：
> - **开发期**：浏览器形态（`file://` 双击即用 + 本地 Node 代理），零改动沿用现有代码
> - **最终交付**：**Tauri 桌面应用**——环境自包含，用户只需安装一个 App，无需安装 Node

---

## 1. 背景与目标

### 1.1 为什么接入 AI

紧固件贸易工作台是一个纯离线单页应用，已覆盖订单、客户、供应商、结算、发票等完整业务数据。但数据的**整理、分析、洞察**仍依赖人工：

| 现状痛点 | AI 能做什么 |
|---|---|
| 每月手工算经营总结 | 自动生成月度经营报告 |
| 催款话术每次重写 | 根据订单/金额/到期日一键生成话术 |
| 供应商比价靠脑子记 | 跨全部历史报价自动比价、推荐最优 |
| 客户好不好凭感觉 | 交易频次/毛利率/回款周期数据驱动分析 |
| 利润靠手算 | 每单实时核算 + 趋势分析 |
| 找个数据翻半天 | 自然语言问答："上个月王经理还欠多少？" |

### 1.2 设计原则

1. **离线优先不变**：AI 是渐进增强，不联网时应用 100% 正常运行，不降级、不报错
2. **零依赖不变**：不引入 npm/框架/构建工具，新增代码遵循原生 `<script defer>` 加载
3. **密钥不落盘**：API Key 仅存于本地代理或桌面端进程内存；不写入浏览器存储、代码或项目文件
4. **数据可控**：每次发送前均可审阅数据快照；默认脱敏，不发送税号、银行账户、地址及完整联系人信息
5. **按需使用**：用户主动打开 AI 面板才激活，不后台运行、不自动调用
6. **单人单机**：不需要多用户/权限/服务端，一切在用户本机完成

## 2. 技术约束分析

### 2.1 DeepSeek API 特性

| 属性 | 值 |
|---|---|
| API 端点 | `https://api.deepseek.com/chat/completions` |
| 协议 | OpenAI 兼容（`/v1/chat/completions` 同义） |
| 认证 | `Authorization: Bearer {API_KEY}` |
| 默认模型 | `deepseek-v4-flash`（快速、低成本；默认关闭 thinking） |
| 可选模型 | `deepseek-v4-pro`（复杂分析时由用户手动选择） |
| 流式 | 支持 SSE（`stream: true`） |
| 上下文窗口 | 以 DeepSeek 平台实时说明为准；应用按每次请求的实际 usage 记账 |
| 费用 | 以 DeepSeek 平台实时定价为准；应用提供单次输出上限与累计用量提示 |

> `deepseek-chat` 与 `deepseek-reasoner` 为已淘汰的兼容名称，不作为本方案的可选模型。接口与模型/定价均可能调整，实施时应以 DeepSeek 官方文档为准。

### 2.2 CORS 限制（关键约束）

**DeepSeek API 不支持浏览器直接调用**——响应头不包含 `Access-Control-Allow-Origin`，浏览器同源策略会拦截所有前端 `fetch()` 请求。

这意味着：

- ❌ 不能从 `file://` 协议直接 `fetch('https://api.deepseek.com/...')`
- ❌ 不能从任何域名直接调用 DeepSeek API
- ✅ 必须通过后端代理转发（浏览器形态：Node 代理；**Tauri 形态：Rust 命令直连，天然无 CORS**，见 3.4）

### 2.3 与零依赖原则的冲突与调和

AGENTS.md 规定：应用必须 `file://` 双击即用，不需要 HTTP 服务器。

**调和方案**：将 AI 功能定位为**可选增强模块**：

| 层级 | 离线状态 | 在线 + 代理运行 |
|---|---|---|
| 核心功能 | ✅ 100% 正常 | ✅ 100% 正常 |
| AI 面板入口 | 隐藏或显示"需要网络" | ✅ 可用 |
| AI 对话 | 不可用 | ✅ 可用 |
| 快捷指令 | 不可用 | ✅ 可用 |

**核心设计**：AI 模块代码始终加载（`<script defer>`），但只在检测到本地代理在线时激活 UI。代理不运行时，AI 按钮显示灰色提示，不报错、不阻塞。

### 3.2 数据流

```
用户操作
  │
  ├─ 点击 AI 按钮 (⌥+I 或导航栏图标)
  │
  ▼
AI 聊天面板展开 (右侧 Drawer)
  │
  ├─ 用户输入问题 或 点击快捷指令
  │
  ▼
上下文提取器 (ai.js: extractContext)
  │
  ├─ 1. 业务概览快照（统计摘要，~200 tokens）
  ├─ 2. 当前页面上下文（视图感知，~300 tokens）
  ├─ 3. 问题相关实体（关键词匹配，~500-1000 tokens）
  └─ 4. 对话历史（最近 6 轮，~800 tokens）
  │
  ▼
构建 messages 数组
  ├─ system: 角色设定 + 数据快照 + 输出格式要求
  ├─ history: 最近对话
  └─ user: 当前问题 + 上下文标记
  │
  ▼
fetch('http://localhost:7842/chat', { stream: true })
  │
  ├─ 代理转发到 https://api.deepseek.com/chat/completions
  │
  ▼
SSE 流式响应
  │
  ├─ 逐 chunk 解析 data: {...}
  ├─ 提取 delta.content
  └─ 实时追加到聊天面板（打字机效果）
  │
  ▼
响应完成 → 保存到 DB.aiChats → 滚动到底部
```

### 3.3 离线降级

```
应用启动
  │
  ├─ 加载 ai.js（始终加载，不影响性能）
  │
  ├─ 探测代理：fetch('http://localhost:7842/health', { signal: AbortSignal.timeout(800) })
  │     │
  │     ├─ 成功 → AI 面板可用，按钮高亮
  │     ├─ 失败 → AI 按钮显示"未连接"，面板提示"请先启动代理"
  │     └─ 每 30s 重试探测（面板打开时）

  └─ 核心功能不受任何影响
```

### 3.4 桌面应用形态（Tauri，最终交付形态）

#### 3.4.1 为什么选 Tauri

| 维度 | Tauri（选定） | Electron（备选） |
|---|---|---|
| 打包体积 | **~10-15MB** | ~150MB+ |
| 内存占用 | 低（复用系统 WebView） | 高（自带 Chromium） |
| 运行时依赖 | **无**（Rust 后端编译为原生二进制） | Node 已内嵌（包体大） |
| 网络限制 | **Rust 侧原生 HTTP，天然无 CORS** | 主进程 Node 转发 |
| 现有代码迁移 | 静态文件直接作为前端资源，**业务代码零改动** | 同样零改动 |
| 维护成本 | 改代理逻辑需触碰少量 Rust（一次性写好） | 全 JS，但包体/内存代价永久存在 |

**关键收益**：Tauri 的 HTTP 请求走 Rust 侧原生实现，**不存在浏览器同源策略**——`tools/ai-proxy.js` 的转发职责由 Rust 层直接承担，且 API Key 可只存 Rust 进程内存，安全模型不变。

#### 3.4.2 Tauri 架构

```
┌─────────────────────────────────────────────────────────────┐
│                 Tauri 桌面应用 (紧固件贸易工作台.app)          │
│                                                             │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  WebView（系统 WKWebView / WebView2）                  │  │

│  │  AI 模块：js/ai.js + js/views/ai-chat.js              │  │
│  │    ├─ 检测到 Tauri 环境 → 走 invoke() 调 Rust 命令     │  │
│  │    └─ 检测到浏览器环境 → 走 localhost 代理（开发期）    │  │
```

#### 3.4.3 AI 模块的双通道适配

`js/ai.js` 运行时探测环境，自动选择通道（业务代码对此无感知）：

```javascript
// 通道选择（ai.js 内部）
const IS_TAURI = !!(window.__TAURI_INTERNALS__);  // Tauri v2 全局标记

// Tauri：IPC 调 Rust 命令，无 CORS、无端口、无额外进程。
// tauri.conf.json 须显式启用 withGlobalTauri。
if (IS_TAURI) {
  const { invoke, Channel } = window.__TAURI__.core;
  const onChunk = new Channel();
  onChunk.onmessage = chunk => appendAIChunk(chunk);
  await invoke('ai_chat_stream', { requestId, messages, model, onChunk });
}
// 浏览器（开发期）：走 localhost:7842 Node 代理
else {
  await fetch('http://localhost:7842/chat', { method: 'POST', ... });
}
```

Tauri 的 `invoke` 参数不能传递 JavaScript 回调函数；流式 HTTP 响应必须通过 `Channel` 发送 chunk。每次请求生成 `requestId`，用户停止生成时调用 `ai_abort(requestId)`，Rust 侧以取消令牌中止上游 HTTP 流。

**统一收益**：聊天面板、快捷指令、上下文提取（第 4-7 章）全部复用，只有最底层的「发送」函数分叉。

#### 3.4.4 密钥安全模型（不变）

| 环节 | 浏览器形态 | Tauri 形态 |
|---|---|---|
| Key 输入 | 启动时从 `DEEPSEEK_API_KEY` 环境变量读取 | AI 面板设置框 |
| Key 存储 | Node 代理进程内存（不落盘） | Rust 进程内存（不落盘） |
| Key 注入 | 代理转发时加 Bearer 头 | Rust 转发时加 Bearer 头 |
| 关闭清除 | Ctrl+C 进程退出即清 | App 退出即清 |
| 前端可见性 | ❌ 代理不返回 Key | ⚠ 输入时经过 WebView IPC，保存后不返回、不持久化 |

#### 3.4.5 桌面化前置改造清单（必须完成）

| # | 改造项 | 原因 | 工作量 |
|---|---|---|---|
| 1 | **现有本地依赖验收**：确认 `xlsx-js-style` 本地优先加载在 WebView 中可用 | 当前项目已完成本地化，桌面端需回归验证 | 小 |
| 2 | **现有 JSON 迁移验收**：用数据管理页的全量 JSON 导入/导出，将浏览器数据迁入 App | 当前项目已有入口，补充迁移测试与说明 | 小 |
| 3 | **Tauri 工程骨架**：`src-tauri/`（权限、CSP、命令白名单、Channel 流式命令） | 明确 IPC 边界与安全策略 | 中 |
| 4 | **打包脚本**：按目标平台构建 macOS/Windows 安装包 | 构建环境需 Node 与 Rust；用户侧不需要 Node | 小 |
| 5 | **AGENTS.md 更新**：增加 Tauri 构建目录的明确豁免范围 | 保留根目录 `index.html` 的直接打开能力 | 小 |

**注意**：桌面化是**叠加**而非替换。Tauri 产物是平台应用/安装包，不是单个 HTML 文件；项目根目录的浏览器形态仍必须保持 `file://` 双击可用。

#### 3.4.6 用户视角对比

| 用户操作 | v1.0 方案（Node 代理） | v2.0 方案（Tauri） |
|---|---|---|
| 首次使用 | 安装 Node.js → 终端启动代理 → 打开工作台 | **双击安装 App，完成** |
| 日常使用 | 每次先启动代理再打开工作台 | 打开 App 即用 |
| AI 功能 | 代理没启动则灰色 | App 内置，联网即用 |
| 数据位置 | 浏览器 IndexedDB | App 数据区（可从浏览器迁移） |
| 卸载残留 | Node + 代理脚本 + 浏览器数据 | 拖入废纸篓即净 |

### 4.2 快捷指令（预设 Prompt）

| 指令 | 发送内容 | AI 行为 |
|---|---|---|
| 经营总结 | "请根据以下数据生成本月经营总结，包括销售额、利润、回款率、客户活跃度、待办事项" | 生成结构化月度报告 |
| 催款建议 | "请分析所有应收未收款项，按紧急程度排序，给出催款优先级和建议" | 分析未收款项 + 排序 + 话术 |
| 比价分析 | "请分析所有供应商的报价数据，找出各规格性价比最高的供应商" | 跨规格比价 + 推荐 |
| 客户分析 | "请分析所有客户的交易频次、累计金额、毛利率，给出客户分级建议" | 客户画像 + 分级推荐 |
| 话术生成 | "请为以下客户的未收款项生成催款微信消息，语气友好但坚定" | 逐客户生成催款话术 |

## 5. 本地代理设计（浏览器形态 / 开发期方案）

> **定位说明**（v2.0）：本章代理服务于**浏览器形态**（`file://` + Node）。Tauri 桌面形态下，同等职责由 Rust 命令承担（见 3.4.2），本代理仍是开发调试与「未安装桌面 App 时」的降级通道。

### 5.1 设计目标

- 极简：一个文件、零依赖（仅用 Node.js 内置模块）
- 安全：API Key 与随机会话令牌仅存在代理进程内存中，不落盘
- 轻量：启动即用，关掉即走
- 友好：启动时打印使用说明、端口冲突自动提示

### 5.2 代理文件 `tools/ai-proxy.js`

**技术选型**：仅使用 Node.js 内置模块（`http`、`https`、`url`），不依赖任何 npm 包。

**核心逻辑**：

```
启动：DEEPSEEK_API_KEY=sk-xxx node tools/ai-proxy.js [--port=7842]

1. 启动 HTTP 服务器，固定监听 `127.0.0.1:{port}`；端口被占用时停止并明确提示
2. 从 `DEEPSEEK_API_KEY` 环境变量读取 Key，并生成随机会话令牌
3. 路由：
   GET  /health → 返回 { ok: true, hasKey: bool, model: 'deepseek-v4-flash' }
   POST /chat   → 接收 { messages, model, stream, temperature }
                 → 校验 `X-AI-Session` 会话令牌
                 → 转发到 https://api.deepseek.com/chat/completions
                 → 透传 SSE 流式响应（或非流式 JSON）
4. 关闭时清除内存中的 Key 与会话令牌
```

**关键实现要点**：

- **访问控制**：为兼容 `file://` 可返回 CORS 响应，但不得仅依赖 CORS；不提供 `/key` 接口，所有业务请求必须携带随机会话令牌，避免任意网页滥用本机代理与 API 额度
- **SSE 透传**：流式模式下，代理逐 chunk 转发，不缓冲全部响应
- **密钥注入**：代理在转发时注入 `Authorization: Bearer {key}`，前端不需要传 Key
- **请求约束**：白名单模型（默认 `deepseek-v4-flash`）、限制请求体与 messages 数量、限定 `max_tokens`，拒绝未知字段
- **错误处理**：DeepSeek 返回错误时，透传 HTTP 状态码和错误体
- **取消与超时**：客户端断开或用户停止时销毁上游请求；单次请求 120s 超时
- **日志**：不记录请求体、响应体、Key 或会话令牌

### 5.3 启动方式

```bash
# 推荐：由当前终端会话提供 Key，关闭代理后自动失效
DEEPSEEK_API_KEY=sk-xxx node tools/ai-proxy.js
```

不得使用 `--key`：命令行参数可能留在 shell 历史或进程列表。浏览器形态不接受前端提交的 Key；若没有环境变量，代理仅报告“未设置 Key”。会话令牌启动时仅在本地受控流程中交给工作台，并只保存在当前页面内存。

### 5.4 代理探测

前端启动时和面板打开时，自动探测代理：

```javascript
// ai.js
async function probeProxy() {
  try {
    const r = await fetch('http://localhost:7842/health', {
      signal: AbortSignal.timeout(800)
    });
    if (r.ok) {
      const d = await r.json();
      return { online: true, hasKey: d.hasKey, model: d.model };
    }
  } catch (_) {}
  return { online: false };
}
```

探测策略：
- 应用启动后 2s 探测一次（不阻塞渲染）
- AI 面板打开时立即探测
- 面板打开期间每 30s 重试
- 代理从离线变在线时，自动刷新 AI 按钮状态

### 6.2 上下文提取策略

**核心原则**：Token 预算约 3000 tokens，数据要精不要全；本地先计算金额、利润、到期日和排名，AI 只解释结果和给出建议。

**分层提取**：

```
第1层：业务概览（始终注入，~200 tokens）
─────────────────────────
- 订单总数 X 笔（待确认 A / 寻货中 B / 报价中 C / ...）
- 本月销售额 ¥XXX，利润 ¥XXX（毛利率 X%）
- 应收未收 ¥XXX（X 家客户）
- 应付未付 ¥XXX（X 家供应商）
- 客户 X 家，供应商 X 家
- BOM 规格 X 种

第2层：页面上下文（按当前视图注入，~300 tokens）
─────────────────────────
例：在订单列表页
- 当前显示 X 条订单
- 最近 5 条：PO260805-001 | 华东机械 | 报价中 | ¥12,000
            PO260805-002 | ...

第3层：问题相关实体（按关键词匹配注入，~500-1000 tokens）
─────────────────────────
关键词命中规则：
- "催款"/"应收"/"未收" → 注入全部未结应收明细
- "供应商"/"比价"/"采购" → 注入供应商列表 + 报价统计
- "客户"/"分析"/"画像" → 注入客户交易汇总
- "利润"/"赚"/"亏" → 注入订单利润排行
- "交期"/"送货"/"到货" → 注入在途订单 + 交期
- 具体 SKU/客户名 → 注入该实体详情
- 无命中 → 只注入第1+2层

第4层：对话历史（最近 6 轮，~800 tokens）
─────────────────────────
- 只取最近 3 组问答（6 条消息）
- 超出的历史不注入
```

**数据格式**：紧凑键值对，不用完整 JSON，节省 tokens：

```
【经营概况】
订单: 15笔 | 本月销售额: ¥125,000 | 利润: ¥18,500(14.8%)
应收未收: ¥32,000(3家) | 应付未付: ¥15,000(1家) | 客户: 5家 | 供应商: 3家

【当前页面: 采购订单列表】
显示10条/共15条
PO260805-001 华东机械 报价中 ¥12,000
PO260806-002 上海机泵 寻货中 ¥8,500
...

【应收未收明细】
华东机械(U1) 主力 应收¥12,000 到期8/20 超5天
上海机泵(U3) 备选 应收¥15,000 到期8/25 剩2天
宁波液压(U5) 新客 应收¥5,000 到期9/01 剩12天
```

### 6.3 确定性计算与 AI 叙述分层

以下结果必须由本地只读聚合器 `AIContext` 计算：订单销售额/采购成本/利润、应收应付余额、回款率、逾期天数、客户与供应商排行。AI 不得自行重新汇总原始金额或推算日期。

`AIContext` 输出“计算口径 + 结果 + 来源订单 ID”的紧凑快照；`buildSystemPrompt()` 要求模型仅基于快照解释、总结、排序和生成话术。若字段缺失、数据冲突或问题超出快照，回复必须明确说明，不能补造数据。

### 6.4 System Prompt 设计

```
你是一个紧固件贸易助手的 AI 后端。用户是一个做紧固件贸易的个人中间商，
同时管理采购商（客户）和供应商两边关系。

你的职责：
1. 基于提供的业务数据，回答用户关于订单、客户、供应商、结算、利润的问题
2. 生成催款话术、经营总结、分析报告等实用内容
3. 给出数据驱动的建议（催款优先级、供应商选择、客户分级）
4. 如果数据不在提供的快照中，明确告知用户

输出规则：
- 金额用 ¥ 符号 + 千分位（¥12,000）
- 日期用 YYYY-MM-DD 格式
- 表格用 Markdown 表格
- 分析结论用加粗 + 列表
- 催款话术用引用块，方便用户复制
- 不要编造数据，只使用提供的快照
- 金额、日期、逾期与排名均以本地计算结果为准，不自行重算

以下是用户当前的业务数据快照：

```

## 8. API 密钥管理

### 8.1 密钥流向

```
用户获取 DeepSeek API Key
  │
  ├─ 浏览器形态：由当前终端会话的环境变量传入
```

**安全保证**：
- API Key 永远不写入浏览器 localStorage / IndexedDB / 代码
- API Key 永远不写入项目文件
- 浏览器形态的 Key 只存在于代理进程内存中，代理关闭即清除
- Tauri 形态的 Key 只存在于 Rust 进程内存中，App 退出即清除
- 浏览器形态不接受网页提交 Key，所有 `/chat` 请求均须附带会话令牌

### 9.2 隐私保证

| 数据 | 存储位置 | 是否发送给 DeepSeek |
|---|---|---|
| 业务数据（订单/客户/供应商） | 本机 IndexedDB | ✅ 仅发送用户确认的脱敏快照 |
| API Key | 代理进程内存 | ❌ 不发送给浏览器，只发送给 DeepSeek |
| 对话历史 | 本机 IndexedDB | ✅ 作为上下文发送最近 6 条 |
| 联系人电话/微信/地址 | 本机 IndexedDB | ❌ 默认不注入；用户显式选择后按规则脱敏 |
| 开票信息（税号/银行账号） | 本机 IndexedDB | ❌ 不注入上下文 |

### 9.3 用户控制

- **发送前审阅**：首次使用、全量分析及含联系人信息的请求，均须先显示并确认待发送快照
- **最小化发送**：默认不发送电话、微信、地址、税号、银行账户和完整备注；电话如获授权，仅显示前 3 后 4 位
- **查看发送内容**：每条 AI 回复下方可展开"查看发送的数据快照"，供事后审计
- **清空历史**：设置中可一键清空所有对话历史

## 12. 代理脚本设计细节

### 12.1 `tools/ai-proxy.js` 核心逻辑伪代码

```javascript
// 关键约束伪代码（仅 Node.js 内置模块）
const PORT = getFixedPortOrExit(7842); // 禁止自动跳到未知端口
const DEFAULT_MODEL = 'deepseek-v4-flash';
const apiKey = process.env.DEEPSEEK_API_KEY || '';
const sessionToken = crypto.randomBytes(32).toString('base64url');

// /health：仅返回 online/hasKey/model，不返回 Key 或 sessionToken
// /chat：先校验 X-AI-Session === sessionToken，再校验 body 的模型、字段、大小及 max_tokens。
// 上游 HTTPS 请求仅由代理添加 Authorization；逐 chunk 透传 SSE。
// req.aborted / res.close / 120 秒超时：立即 destroy 上游请求。
// 代理不实现 POST /key，不记录请求体、响应体、Key 或 token。
// file:// 兼容所需的 CORS 不是访问控制；会话令牌才是必要能力凭证。
```

### 12.2 代理安全措施

- **只监听 127.0.0.1**：不接受外部网络请求
- **Key 不落盘**：纯内存，进程退出即清除
- **会话令牌**：`/chat` 必须校验随机 `X-AI-Session`；不能把“仅监听 localhost”视为网页访问控制
- **CORS 非授权机制**：`file://` 场景可使用 CORS 响应头，但必须允许 `X-AI-Session` 预检且不能以来源头代替会话令牌；不能提供可被网页调用的 `/key`
- **参数白名单**：只允许 `deepseek-v4-flash`（及用户明确启用的 `deepseek-v4-pro`），限制请求大小、历史条数和输出 token
- **不记录日志**：代理不记录任何请求内容
- **取消与超时**：客户端断开或用户停止时销毁上游请求；上游 120s 超时，防止挂起

## 15. 总结

| 维度 | 方案 |
|---|---|
| **默认模型** | `deepseek-v4-flash`；后续可由用户手动启用 `deepseek-v4-pro` |
| **交付形态** | 双轨：浏览器形态（file:// + 安全本地代理）→ 可选 Tauri 桌面应用（用户侧无需 Node） |
| **接入方式** | Tauri：Rust `Channel` 流式转发；浏览器：带会话令牌的本地 Node 代理 |
| **核心约束** | 不破坏 file:// 离线优先原则，AI 为渐进增强；桌面化为叠加而非替换 |
| **密钥安全** | API Key 只在 Rust / Node 代理进程内存中；浏览器代理仅从环境变量读取，禁止 `/key` 与通配 CORS |
| **数据安全** | 发送前审阅、默认脱敏、最小化发送；业务数据仍全存本机 |
| **数据可信度** | 金额、日期、逾期和排行由本地 `AIContext` 计算，AI 只做解释与建议 |
| **功能范围** | 7 个快捷指令 + 自由问答 + 上下文感知 + Markdown 渲染（两种形态完全复用） |
| **代码量** | 新增 ~1200 行（Tauri 工程 240 + 代理 80 + ai.js 380 + ai-chat.js 400），修改 7 个文件 |
| **实施顺序** | Phase 0 安全与本地计算 → Phase A 可用 → Phase B 好用 → Phase C 可选桌面化 → Phase D 打磨 |
