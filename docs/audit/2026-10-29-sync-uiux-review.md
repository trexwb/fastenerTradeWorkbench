# 「数据同步」页面 UI/UX 审查报告

> **日期**: 2026-10-29 ｜ **对象**: 新增「数据同步」视图（`src/views/sync.js` + `src/core/sync.js` + `src-tauri/src/sync_server.rs`），及数据管理页中的同族同步区块（本地文件同步卡 / 立即同步 / 解绑）
> **方法**: 全文读源码 + Tauri Rust 端点核对 + 浏览器实际渲染取证（mock 桌面态快照 + 计算样式探针）+ UI/UX 启发式检查（状态完整性/文案/可访问性/视觉规格）
> **结论**: 已修复功能性缺陷 3 条、交互与文案 6 条、可访问性 2 条；另有 6 条设计级建议仅记录未动。**改动未构建验证**。

---

## 一、取证说明（结论可信度）

- **file:// 打开报 CSP 错误为审查环境限制，非产物缺陷**：本审查面板以自定义协议（zwork-workspace-file:）代理工作区文件，首次加载被面板侧 CSP（`script-src 'self' 'unsafe-inline'`，无 unsafe-eval）拦截。经核实：`dist/index.html` 无任何 CSP meta（src 注释明确 Tauri CSP 由 tauri.conf.json 注入），产物内 `(0,eval)` 实测可用——真实双击 file:// 场景不受影响。
- **桌面态视觉取证**：面板内 mock `SYNC.isTauri` + 状态数据后实际渲染整页（快照 + getComputedStyle 探针），核对了布局、配色、字体、控件状态。
- **Rust 能力面核对**：`sync_server.rs` 当前仅 `/api/sync/ping`（健康检查）与 `/api/sync/hello`（配对确认，客户端超时 130s，确认等待 CONFIRM_TIMEOUT）两个端点——**尚无数据传输端点**，仅入站请求有 Tauri 事件。

## 二、信息架构与布局

**做对的**：
- 页面结构清晰：设备身份 → 同步服务（本机地址/连接码）→ 连接对端 → 已连接设备，符合「先表明我是谁、再提供服务、再去连接」的心智顺序；每卡有图标+标题+状态 tag（运行中/未启动）。
- 连接码用 36px 大字 + 8px 字距 + 等宽字体 + `user-select:all`，单击即全选，复制/刷新就在旁边——这是全页最好的设计。
- 绑定前置预提示弹窗（store.js bindFile）逐条解释两次系统授权、系统文件夹限制与应对——优秀的防困惑设计。

**发现并已修**：
- 浏览器版空态是**死路**：只有一句「数据同步仅在桌面版中可用」，无原因、无出路。已改为：说明需要桌面版本地网络能力的原因 + 指出网页版替代方案（数据管理的本地文件同步/自动备份）+ 「前往数据管理」按钮。
- 表单行 `label` 全部无 `for` 关联（违反项目 §12.2），点击标签不聚焦输入框、读屏器无关联——已补 5 组 for/id（设备 ID/昵称/端口/对方地址/连接码）。

**设计建议（未动）**：
1. **期望管理（本页最大的 UX 缺口）**：副标题写「数据同步与传输」，但当前只有配对能力，连接成功后没有任何传输操作或进度呈现——用户连接后不知道下一步做什么。建议：传输端点就绪前，把副标题收敛为「局域网内设备配对与连接」，或在「已连接设备」卡加一行「数据传输功能即将上线」占位；上线后此处应有传输记录/进度区块。
2. 卡片全宽拉伸但表单列仅 ~280px，宽屏下左右失衡；建议内容容器 `max-width:720px` 居中（与本页表单型布局匹配）。
3. 设备 ID 显示完整 UUID 信息密度低：建议列表中显示前 8 位、悬停/复制取全量。
4. 「停止服务」会断开所有会话，建议加 confirmModal 二次确认（断开单连接属轻量操作，无需确认）。

## 三、交互与状态完整性

**发现并已修（功能性缺陷 3 条）**：
1. **按钮 loading 错位（P1）**：`_syncStartServer` 的按钮定位 `getElementById('syncConnectBtn') || 端口输入框兄弟节点`——前者恒存在（连接对端卡总在渲染），于是点「启动同步服务」转圈的是**连接按钮**，启动按钮自身无任何反馈；`_syncStopServer` 用 `querySelectorAll('.btn.danger')` 取最后一个——拿到的是**已连接设备行的「断开」按钮**（渲染在停止按钮之后）。已改为各自 `syncStartBtn`/`syncStopBtn` id 定位。
2. **刷新后状态丢失（P1）**：`window._syncStatus` 仅存内存，页面刷新后为 null 而 Rust 服务仍在跑——页面误显「未启动」，用户再次启动会吃端口冲突错误。已在 viewSync 渲染后异步拉取 `getServerStatus()` 回填（带 `view==='sync'` 守卫）。
3. **已连接设备表永久滞留（P1）**：Rust 仅对入站请求 emit 事件，对端主动断开本端无感知，列表停留旧状态。已加 10s 轮询（仅同步视图可见期间，离开自动停；会话列表变化才重渲染）。

**其余交互修复**：
- 端口输入无校验（0/负数/超 65535 直接透传 Rust）→ 前端拦截 + toast + 焦点，input 补 min/max。
- 连接码倒计时归零只留红字「已过期」→ 补引导文案（过期后旧码必然失败，请点刷新）。
- 断开按钮依赖全局 `event` 隐式变量 → 改显式传 `this`。
- 数据管理页同族：`syncNow` 写失败时异常静默抛出（无 toast、无渲染，用户以为成功）→ 补 catch toast + 按钮 loading；`_renderWebDataLocation` 的 promise 补 catch（失败不再永久停留「正在获取…」）。

**已核实无问题**：昵称保存（防重+loading+恢复）、连接流程（地址清洗 http:// 前缀、6 位码校验、失败复位按钮）、连接成功/被接受后的状态刷新、倒计时定时器在视图切换时的清理、复制功能的降级提示、入站确认弹窗的昵称/设备 ID 均过 escHtml（html=true 无注入面）。

## 四、文案与微文案

- **已修（误导性错误）**：解绑确认框写「解绑后数据将仅保存在浏览器 **localStorage**」——主存储是 IndexedDB，localStorage 只存表单草稿；原文案会让用户以为解绑丢业务数据。已改为准确表述并附替代备份指引。
- **已修**：「已同步」卡在无最后同步时间时会渲染出悬空的「 · 」分隔符；数据管理页 localStorage 标题 `style="data-section-hd"` 笔误导致样式类从未生效。
- **建议（未动）**：「本机地址（告知对方）」中 127.0.0.1 也会出现在地址列表里（Rust 兜底 push），对对方不可达，建议前端过滤或标注「仅本机」；连接码有效期 300s 为前端硬编码，若 Rust 调整过期时长会不同步，建议以服务端返回为准。

## 五、可访问性

- **已修**：5 组 label 补 for/id；异步填充区（storageQuota / dataLocationInfo）补 `aria-live="polite"`（async 填充对读屏器可感知）；`.data-tab` 补 `:focus-visible` 焦点环（键盘 Tab 导航此前无可见焦点）。
- **实测对比度（通过）**：--pri #3b5998 连接码在 --pri-l 底上 ≈6.5:1；--gray #6f6862 在 card/bg-soft/green-l 上 ≈4.7–5.5:1，12px 正文均达 AA（≥4.5:1）；暗色主题变量齐备（green-l/amber-l/red-line 均有 dark 值）。
- **已核**：状态不只靠颜色（tag 均带文字）；按钮均为原生 button（键盘可达）；倒计时变红同时伴随文字变化。
- **建议（未动）**：data-tabs 可补 `role="tablist"/tab` + `aria-selected`（本项目其他 tabs 亦未做，建议统一一次补齐）；「运行中」tag 可加呼吸动画增强活跃感知（纯装饰，可选）。
