## 1. 快速入门

### 打开工作台

用 Chrome 或 Edge 浏览器直接打开 `src/index.html` 文件即可，无需安装任何软件或联网。

> Safari / Firefox 可使用全部核心功能，但不支持本地文件自动同步（回退为手动导出导入）。

首次打开会看到预置的示例数据（关联单位、报价、订单）。可以随时在「数据管理」中清空示例数据。

桌面版（macOS）以 `.app` 形式分发，启动后与浏览器版功能一致，并额外支持：本地数据目录存储、自动备份子目录、应用自动更新、API Key 保存在应用数据目录（而非 localStorage）。

### 界面布局

│  导航     │                                  │

- **PC 端**：左侧固定侧边栏导航，顶栏右侧含全局搜索按钮（⌘K）
- **手机端**：点击左上角汉堡菜单展开侧边栏，底部适配安全区

### 推荐首次操作顺序

1. 「规格管理」→ 确认六个维度的枚举值是否够用，按需增删
2. 「关联单位」→ 录入供应商和采购商
3. 「BOM 管理」（可选）→ 维护标准产品目录，方便快速引用
4. 「价格管理」→ 录入供应商的初始报价
5. 「采购订单」→ 创建第一笔订单
6. 「数据管理」→ 绑定本地文件，开启自动备份
7. （可选）「AI 助手」→ 在设置中填入 API Key，开始用自然语言分析数据/起草操作

## 2. 概览页

概览页是工作台的首页，打开即见当前需要处理的事项。

### 今天要处理

页面顶部自动汇总三类需要关注的订单，点击「处理」直接跳转到订单详情页：

| 标识 | 含义 |
|------|------|
| **红色「逾期 × 天」** | 已超过交货期仍未完成的订单 |
| **「距交期 × 天」** | 交货期临近（3天内）的订单 |
| **状态名称** | 待确认、寻货中、待签约等未完成订单 |

### 统计卡片

| 卡片 | 含义 |
|------|------|
| 采购订单总数 | 所有订单（含完成/取消） |
| 待处理订单 | 待确认 + 寻货中 + 待签约 |
| 本月签约额 | 当月状态为「签约完成」及之后各状态的订单销售总额 |
| 供应商数 | 角色中包含「供应商」的关联单位数量 |

### 最近订单

最新 8 条订单的简要列表，每条显示：单号、采购商、交期、状态标签。点击「查看」进入详情。

## 3. 关联单位管理

管理供应商和采购商。一个单位可同时具备两种角色。

### 新建关联单位

1. 点击右上角「+ 新建关联单位」
2. 填写表单：

| 字段 | 说明 | 是否必填 |
|------|------|:---:|
| 单位名称 | 单位全称 | 是 |
| 角色 | 可多选：供应商 / 采购商 | 是 |
| 结算账期 | 如「月结30天」「款到发货」 | 否 |
| 合作评级 | 主力 / 备选 / 新客 | 否 |
| 开票信息 | 税号、地址、电话、开户行、账号（发票管理中自动引用） | 否 |
| 备注 | 其他备注 | 否 |

3. 点击「保存」完成

> **同一单位的供应商联系人和采购商联系人独立管理**：添加联系人时，选择「供应商」或「采购商」标签加以区分。

### 编辑 / 删除

- **编辑**：点击表格行「编辑」按钮，修改后保存
- **删除**：点击「删除」按钮。删除后该单位进入**回收站**（可在数据管理页恢复），已被订单或报价引用的记录会显示为单位 ID

### 搜索

支持按单位名称、联系人姓名、电话、角色、评级、账期模糊搜索。回车或点击放大镜触发搜索（不在输入时实时触发，避免中文输入法冲突）。

### 草稿自动保存

新建关联单位时，填写过程中数据自动保存为草稿。关闭页面后再次点击「新建」会弹窗提示恢复草稿或放弃。

## 4. 规格管理

管理六个规格维度的可选枚举值，这些值在价格管理、订单和 BOM 中被引用。

### 六个维度

| 维度 | 示例枚举值 |
|------|-----------|
| 类型 | 螺栓、螺母、垫圈、螺钉、自攻钉、木螺钉、膨胀螺栓、销钉、挡圈、螺柱 |
| 标准 | GB/T、DIN、ISO、ANSI/ASME、JIS、非标、HG、JB |
| 直径 | M3、M4、M5、M6、M8、M10、M12…M42 |
| 硬度 | 4.8、5.8、6.8、8.8、10.9、12.9、A2-70、A4-80… |
| 表面处理 | 本色、镀锌(白)、镀锌(彩)、镀镍、达克罗、发黑、磷化、钝化 |
| 材质 | 304、316、316L、321、201、Q235、Q345、35#、45#、SCM435、40Cr、B7 |

### 新增枚举值

在每个维度下方的输入框中输入新值，按回车即可添加。

### 删除枚举值

点击已有值标签右侧的「×」即可删除。删除后该值进入回收站，可在数据管理页恢复。

> **注意**：删除枚举值不影响已使用该值的报价和订单记录，但后续新建时无法再选择该值。

## 5. BOM 管理

BOM（Bill of Materials，物料清单）用于维护标准产品目录。一个 BOM 记录包含 SKU、名称、规格描述和六个属性维度。

BOM 可被报价管理和采购订单直接引用，实现快速填充规格字段。

### 新建 BOM

1. 点击右上角「+ 新建BOM」
2. 必填字段：SKU、名称、规格
3. 其他属性（类型/标准/直径/硬度/表面处理/材质）可通过下拉选择已有枚举值，或直接输入新值
4. 点击「保存」完成

> **SKU 唯一性**：同一 SKU 不可重复，表单会实时校验并阻止重复保存。

### 批量导入

当需从 Excel 或 CAD 表格中批量导入 BOM 时使用：

1. 从 Excel/CAD 中复制数据（Ctrl+A → Ctrl+C）
2. 点击「批量导入」→ 粘贴到文本框
3. 点击「解析」预览，系统自动识别表头并跳过
4. 可在预览中逐行删除不需要的条目
5. 点击「批量提交」确认

支持列顺序：SKU或名称 | 表面处理 | 规格 | 标准 | 直径 | 硬度 | 材质

### 筛选与搜索

- **搜索框**：按 SKU 或名称模糊搜索
- **六维度筛选**：每个维度均可下拉筛选，激活时显示「已筛选」徽章
- **批量删除**：勾选多条记录后点击「批量删除」统一删除（软删除，进入回收站）

### BOM 联动引用

在报价管理和采购订单中添加产品时，可从 BOM 列表中选择已有产品，系统自动填入全部属性字段（SKU、规格、六个维度），并锁定字段防止误改。选择「手动输入」可绕过 BOM 自由填写。

## 6. 价格管理

管理供应商的报价记录：供应商 × 规格 × 单价。

### 新增报价

1. 点击右上角「+ 新增报价」
2. 填写表单：

| 字段 | 说明 | 是否必填 |
|------|------|:---:|
| 供应商 | 搜索选择已有供应商，或直接输入新名称 | 是 |
| 联系人 | 选择供应商后自动带出，可修改 | 否 |
| 类型 / 标准 / 表面处理 / 直径 / 材质 / 硬度 | 从下拉选择已有枚举值，或直接输入新值 | 直径/材质/硬度是 |
| 单价（元） | 数字，如 0.35 | 是 |
| 有效期起 | 日期，默认今天 | 否 |
| 备注 | 如「含税」「起订量1000」 | 否 |

3. 点击「保存」完成

> **下拉框用法**：点击展开已有值列表搜索筛选；列表中没有的值直接输入新值按回车即可创建（自动同步到规格管理枚举值）。

### 筛选报价

按供应商和六个规格维度筛选。点击「清除筛选」重置所有条件。

### 编辑 / 删除

- **编辑**：点击「编辑」按钮修改报价
- **删除**：点击「删除」确认后删除（软删除，进入回收站）

> **自动写入**：在采购订单寻货弹窗中手动录入供应商时，系统自动将报价写入价格库，无需重复录入。

## 7. 采购订单管理

工作台核心模块，支持多供应商分配寻源和全流程状态管理。

### 7.1 创建采购订单

1. 点击「+ 新建采购订单」
2. 填写基本信息：

| 字段 | 说明 | 是否必填 |
|------|------|:---:|
| 采购商 | 搜索选择已有采购商 | 是 |
| 对接联系人 | 选择采购商后自动带出 | 否 |
| 项目背景 | 项目描述或用途 | 否 |
| 期望交货期 | 日期选择 | 是 |
| 订单状态 | 默认「待确认」 | 否 |
| 订单备注 | 补充信息 | 否 |

3. 添加产品明细（见 7.2）
4. 点击「保存订单」完成

订单编号自动生成，格式为 `POYYMMDD-序号`，如 `PO260811-001`。

### 7.2 添加产品明细

1. 在订单编辑页点击「+ 添加产品」
2. 可从 BOM 列表选择已有产品自动填充规格，或手动填写：

| 字段 | 说明 | 是否必填 |
|------|------|:---:|
| 类型 / 标准 / 表面处理 | 从下拉选择或输入 | 否 |
| 直径 / 材质 / 硬度 | 从下拉选择或输入 | 是 |
| 数量 | 需求数量，如 5000 | 是 |
| 销售单价 | 元，如 0.85 | 是 |
| 用途 | 如「设备装配」 | 否 |
| 备注 | 特殊要求 | 否 |

3. 点击「添加」完成

可添加多个产品明细，每个产品独立寻源。

### 7.3 供应商寻源（多供应商分配）

一个产品规格可由多个供应商分别供货，因为单个供应商库存可能不足以满足需求。

**操作步骤：**

1. 在产品明细行点击「寻货」按钮
2. 弹窗顶部显示：需求量 / 已分配量 / 剩余量 / 销售价 / 寻源状态
3. **方式一：从价格库匹配**
   - 系统列出价格库中匹配该规格的报价
   - 每条显示：供应商、单价、单位利润、联系人
   - 填写「分配数量」（默认填入剩余量）
   - 点击「+ 添加」加入分配列表
4. **方式二：手动录入**
   - 在弹窗下方手动填写供应商信息
   - 填写采购单价、分配数量、库存/交期备注
   - 点击「保存并添加」
   - **系统自动处理**：新供应商 → 自动创建关联单位（角色=供应商，评级=新客）；自动将报价写入价格库；添加到当前产品供应商分配列表

**寻源状态：**

| 状态 | 条件 | 标签颜色 |
|------|------|----------|
| 待寻源 | 无任何供应商分配 | 红色 |
| 部分寻源 | 分配总量 < 需求量 | 黄色 |
| 已确认 | 分配总量 ≥ 需求量 | 绿色 |

**分配进度条**：每个产品明细行下方显示进度条，绿色=满量，黄色=部分，空白=未寻货。

**管理已选供应商**：在寻货弹窗的「已选供应商」区域点击 × 可移除某个供应商分配。

### 7.4 订单状态流转

```
待确认 → 寻货中 → 报价中 → 签约完成 → 送货中 → 完成
                          ↘ 异常
              ↘ 未成交（可恢复回报价中）
                              ↘ 取消
```

| 状态 | 含义 |
|------|------|
| 待确认 | 订单刚创建，等待确认需求 |
| 寻货中 | 正在匹配供应商、分配采购量 |
| 报价中 | 寻货完成，与采购商报价中 |
| 未成交 | 报价后未签约，可恢复回「报价中」继续 |
| 签约完成 | 合同已签，执行中 |
| 送货中 | 已发货交付（部分完成） |
| 完成 | 全部交付完成 |
| 异常 | 出现问题，需关注 |
| 取消 | 订单已取消 |

### 7.4.1 状态流转按钮矩阵

订单详情页顶部的工具栏提供严格的状态流转控制，**每个状态只能进入上一步或下一步**，不再提供任意切换入口。

| 当前状态 | 上一步 | 下一步 | 标记异常 | 取消 |
|----------|--------|--------|----------|------|
| 待确认 | — | **开始寻货**（校验产品列表 + 意向价） | — | 取消订单 |
| 寻货中 | ← 返回待确认 | **完成寻货**（校验所有产品已分配）→ 进入「报价中」 | — | 取消订单 |
| 报价中 | ← 返回寻货中 | **确认签约** | **标记异常**（终态） | 取消订单 |
| 未成交 | ← 返回报价中 | — | — | — |
| 签约完成 | ← 返回报价中（回退含结算关联时需确认） | **进入送货**（须全部收货） | **标记异常**（终态） | — |
| 送货中 | ← 返回签约完成 | **订单完成** | **标记异常**（终态） | — |
| 完成 | — | — | — | — |
| 异常 | — | — | —（终态，不可恢复） | — |
| 取消 | — | — | —（终态） | — |

> 批量操作：订单列表支持全选/多选（批量删除，进回收站）。

**校验规则**：

- **开始寻货**：订单须有 ≥1 个产品行，且每行都有名称/SKU、规格、意向价。不满足时弹窗提醒，不切换状态。
- **完成寻货**：所有产品须「已确认」（已分配量 ≥ 需求量）。不满足时弹窗提醒，不切换状态。
- **确认签约 / 进入送货 / 订单完成**：需人工确认；进入送货前有收货完整性校验，未齐可「仍然进入送货」强进（留痕）。
- **上一步**：v1.0.27 起从「签约完成/送货中/完成」回退到非结算关联状态时，若该单位已关联结算记录会弹窗确认后才执行。
- **标记异常**（v1.0.27+）：报价中/签约完成/送货中三态可用，进入「异常」**终态（不可恢复）**，与 AI 状态机 `NEXT_STATUS` 一致。
- **取消订单**：「待确认 / 寻货中 / 报价中」三态可用，确认后进入「取消」终态。
- **状态校验统一**：视图层与 AI 工具层共用 `FTValidators`（src/core/validators.js）状态机，消除双轨维护。

按钮旁均有 tooltip 提示具体操作含义。

### 7.5 订单详情页

点击订单列表的「查看」进入，包含：

- **状态流程图**：可视化展示当前进度
- **订单信息**：采购商、对接人、项目、交期、备注
- **产品明细表**：规格、需求量、销售价、供应商分配明细、寻源状态、行利润
- **财务汇总**：销售总额、采购总成本、预估利润
- **导出 Excel**：点击「导出Excel」下载当前订单的 `.xlsx` 文件。不同状态使用不同模板：「待确认」导出**产品确认单**（含勾选确认列，供采购商回填）；「寻货中」导出**寻源进度单**（产品寻源进度表 + 供应商报价对比表，含寻源状态、已分配/剩余量、意向价与采购价差异、行利润、利润率，并在汇总区给出"是否继续寻源 / 意向是否过低"的决策提示）；「报价中/未成交」导出**报价中报价单**（产品明细为主行、对应供应商报价为子行的合并表，含需求/已分配/缺口与满足状态，并在「供应数量提醒」区对未满足需求数量的产品逐项红色醒目提示，避免带缺口签约）；「签约完成」导出**签约完成结算单**（重点为采购商应收明细与供应商应付明细，含已收/已付/未结金额与红色结算提醒）；「送货中/完成」导出**送货结算单**（两状态内容一致仅文件名不同；含结算明细、快递至采购商的地址/单号/时间，及供应商邮寄信息——各供应商按联系人/电话/邮寄地址将产品快递至我方，链路：供应商→我方收货验货→采购商）

### 7.6 搜索与筛选

- **搜索框**：支持单号、采购商、对接人、项目、交期、状态、产品规格、备注模糊搜索
- **状态筛选**：下拉选择特定状态，与搜索可叠加
- 实时显示匹配数/总数

### 7.7 草稿自动保存

表单数据（产品明细、供应商分配）在填写过程中自动保存。关闭页面后再次点击「新建」会弹窗提示恢复或放弃。

## 8. 结算管理

结算管理分为「收款」（向采购商收取）和「付款」（向供应商支付）两个维度，基于「签约完成」及之后各状态的订单数据自动计算应收/应付金额。

> **入口**：仅在侧边栏可见，结算记录由用户在结算管理中手动新增，系统不会自动生成结算记录。

### 8.1 收款管理

按采购商聚合，显示每个采购商的应收总额、已收金额、未收金额和结算状态。

**关联条件**：订单的 `buyerId` 与采购商单位匹配，且订单状态为「签约完成」「送货中」或「完成」。

**结算记录**：每次手动新增结算时，勾选关联订单，系统按勾选订单的未结金额比例自动分配本次结算金额到各订单。

### 8.2 付款管理

按供应商聚合，显示每个供应商的应付总额、已付金额、未付金额和结算状态。

**关联条件**：订单产品明细中分配了某供应商（`supplierId`），且订单状态为「签约完成」「送货中」或「完成」。

### 8.3 新增结算记录

1. 进入「收款」或「付款」Tab
2. 点击「新增结算记录」
3. 选择单位（自动过滤角色）、结算日期、结算金额
4. 勾选关联订单（可选，系统自动汇总未结金额填入结算金额）
5. 填写经手人、备注
6. 点击确认保存

> **自动汇总**：勾选订单后，系统自动将所有勾选订单的未结金额之和填入结算金额输入框。

### 8.4 查看结算明细

点击采购商/供应商行的「明细」按钮，打开抽屉，可看到：

- **汇总信息**：应收/应付总额、已收/已付金额、未收/未付金额
- **关联订单**：每个订单的应收/应付、已收/已付、未结金额和结算状态
- **产品明细**：按订单分组的采购产品列表（含 SKU、规格、单价、数量、总额）
- **结算记录**：该单位所有历史结算记录，可删除

### 8.5 子Tab筛选

每个主Tab下有「未结（X家）/ 已结清（X家）」两个子Tab，点击切换显示不同结算状态的单位列表。点击统计卡片也可快速切换。

## 9. 发票管理

发票管理自动从结算记录同步生成开票/收票任务，无需手动录入开票信息。**每一笔结算记录生成一条发票任务**，用户仅需补充开票日期、状态、抬头等后续处理信息。

> **开票 Tab**：向采购商开票（收款业务）
> **收票 Tab**：向供应商收票（付款业务）

### 9.1 数据同步机制

- **自动生成**：每次进入发票管理页面，系统自动扫描结算记录，为每笔结算生成一条发票任务（`settleId` 唯一，同一结算不会重复生成）
- **自动更新**：结算记录金额、备注变更后，对应的发票任务金额同步更新
- **状态独立**：发票状态（未开/已开/已作废；未收/已收/已认证）与结算状态相互独立

### 9.2 发票任务列表

按采购商/供应商聚合显示，每个单位的每笔结算单独一行，显示：

| 列 | 说明 |
|----|------|
| 结算日期 | 对应结算记录的结算日期 |
| 公司名称 | 结算单位的名称 |
| 应收/应付 | 该结算对应的销售总额（收款）或采购成本（付款） |
| 已收/已付 | 已结算金额（从结算记录取） |
| 未收/未付 | 应收减去已收的差额 |
| 开票/收票状态 | 未开 / 已开 / 已作废（收款）；未收 / 已收 / 已认证（付款） |
| 操作 | 编辑按钮 |

### 9.3 编辑发票

点击「编辑」打开抽屉，补充以下信息：

**收款（开票）专用字段：**

| 字段 | 说明 |
|------|------|
| 开票时间 | 开具发票的日期 |
| 发票号码 | 发票编号 |
| 开票状态 | 未开票 / 已开票 / 已作废 |
| 企业抬头 | 采购商的开票信息（系统自动从关联单位的开票信息填充） |

**付款（收票）专用字段：**

| 字段 | 说明 |
|------|------|
| 收票状态 | 未收票 / 已收票 / 已认证 |

**通用字段：**

| 字段 | 说明 |
|------|------|
| 产品明细 | 从关联订单中读取的实际产品（SKU、规格、数量、单价、金额） |
| 结算备注 | 结算记录中的备注信息，可编辑修改 |

> **企业抬头自动引用**：开票时，系统自动从该采购商单位的「开票信息」字段（税号、地址、电话、开户行、账号）填充到企业抬头输入框。

### 9.4 发票子Tab

每个主Tab下有「未开（X家）/ 已开（X家）」子Tab，分别显示待处理和已完成的开票任务。

## 10. 数据管理与备份

数据管理页采用 **三 Tab 布局**：「数据管理 / 操作历史 / 回收站」，分别承担存储与备份、AI 与用户的操作审计、软删除恢复三类职能。

### 10.1 存储架构

| 层级 | 用途 | 特点 |
|------|------|------|
| **IndexedDB** | 主数据库 | 浏览器本地，容量数百 MB+，所有业务数据存储于此 |
| **本地 JSON 文件** | 持久备份 | 磁盘文件，浏览器清缓存也不丢，每次修改自动写入 |
| **localStorage** | 表单草稿 / 配置项 | 缓存填写中的表单 + AI 设置（API Key 等） |
| **独立 IndexedDB 库** | 知识库 | `wb_fastener_kb`（与业务库隔离），存储知识库分块与索引 |

```
┌──────────────────────────────────────────┐
│           IndexedDB（业务主库）            │
│         wb_fastener_idb / key              │
└───────────────┬──────────────────────────┘
                │  双向同步（时间戳对比）
┌───────────────┴──────────────────────────┐
│        本地 JSON 文件（File System Access API）│
│        └─ backups/ 子目录（自动快照隔离）      │
└──────────────────────────────────────────┘
┌──────────────────────────────────────────┐
│  独立 IndexedDB（wb_fastener_kb）—— 知识库    │
└──────────────────────────────────────────┘
┌──────────────────────────────────────────┐
│      localStorage（表单草稿 + AI 设置）       │
└──────────────────────────────────────────┘
```

### 10.2 数据管理 Tab

#### 绑定本地文件（强烈推荐）

1. 进入「数据管理」页
2. 点击「绑定本地文件」
3. 在文件选择窗口中新建或选择一个 `.json` 文件
4. 授权后，顶栏显示绿色「已同步」标签

> **仅 Chrome / Edge 支持此功能**。Safari / Firefox 用户请使用手动导出导入。

**刷新页面后**（权限失效）：顶栏显示黄色「待授权」标签。进入数据管理页点击「重新授权连接」即可恢复。

**解绑**：点击「解绑」按钮，确认后文件同步功能关闭，数据保留在 IndexedDB 中。

#### 备份提醒与自动快照（v1.0.10 重构）

备份能力拆为两段独立配置，各自有开关与间隔：

| 配置项 | 说明 | 默认 |
|--------|------|------|
| **备份提醒** | 超期未备份时，应用启动后弹窗提醒（一键立即备份 / 稍后提醒），每个周期仅提醒一次 | 关闭 |
| **备份提醒间隔** | 多少天未备份即触发提醒 | 7 天 |
| **自动快照** | 到期自动写入一份完整 JSON 快照到 `backups/` 子目录 | 关闭 |
| **自动快照间隔** | 每 N 天自动备份一次（可选 1/3/7/14/30 天） | 7 天 |
| **保留份数** | 超出后自动删除最旧快照（5/10/20/30/50 份） | 20 份 |

> 旧版 `period`（daily/weekly/monthly/off）配置会自动迁移为 `intervalDays`，无需重新设置；自动快照统一写入备份目录下 `backups/` 子目录，与数据文件隔离。

#### 导出 / 导入备份

| 操作 | 说明 |
|------|------|
| **导出 JSON 备份** | 下载包含全部业务数据的 JSON 文件（不含回收站与操作历史），不限条数 |
| **导入 JSON 恢复** | 选择 JSON 文件覆盖当前数据 |
| **导出 CSV（订单明细）** | 将所有订单明细导出为 CSV 文件 |
| **侧边栏快捷导出** | 随时点击导出备份 |

> 导入会覆盖当前数据，操作前建议先导出一份备份。

#### 知识库区块（v1.0.12 起）

数据管理 Tab 下方独立展示「知识库」区块（与 AI 设置弹窗内的知识库区双入口共享同一状态，任一入口操作即时同步）。详见 [13.7 本地知识库（RAG）](#137-本地知识库rag)。

#### 清空全部数据

1. 点击「清空全部数据」
2. 第一次确认弹窗 → 点击「确认清空」
3. 第二次确认弹窗 → 点击「再次确认清空」
4. 数据清空，恢复初始状态（规格枚举值保留默认值，回收站与操作历史一并清空）

> **警告**：清空操作不可恢复，请确保已导出备份！

### 10.3 操作历史 Tab

记录所有 AI 与用户的写入操作（**不含查询与纯 UI 动作**），支持追溯与回滚。

#### AI 操作统计报表（v1.0.6 起）

Tab 顶部展示全量统计面板（不受筛选影响）：

- **六项指标卡**：总操作 / AI 操作（含占比）/ 用户操作 / 已回滚（含 AI 回滚率）/ 操作批次 / 自动清理
- **操作类型分布**：新增 / 修改 / 删除 / 恢复 / 流转 / 寻货 / 导出 × AI/用户拆分 + AI 占比条形图
- **数据域分布**：单位 / 属性 / BOM / 报价 / 订单 / 明细 / 结算 / 发票 / 导出 的次数 + 占比条形图（降序）
- **近 7 天趋势**：每日操作数 CSS 柱状图（柱顶显示数值，无图表库依赖）

#### 操作历史筛选器（v1.0.5 起）

支持三个维度筛选（切换 Tab 或刷新后丢失，属临时筛选）：

| 筛选维度 | 取值 |
|---------|------|
| 操作类型 | 全部 / 新增 / 修改 / 删除 / 恢复 / 流转 / 寻货 |
| 操作者 | 全部 / AI / 用户 |
| 批次 | 全部 / 前 20 个有未回滚 op 的批次（显示前 8 位） |

#### 自检与整批回滚

- **自检按钮**：检查 aiOps 数据结构、操作记录字段完整性、关键函数（recordAiOp/undoAiOp/undoBatch/softDelete/restoreFromTrash 等）可用性、AIT 模块加载、trash 数组结构共 11 项，弹窗显示结果
- **单条回滚**：每条操作记录右侧「回滚」按钮，反向还原单次操作
- **整批回滚**：同一批次（batchId）的操作可一键整批逆序回滚（创建→删除、修改→还原旧值、删除→恢复），不误伤后续手动改动

### 10.4 回收站 Tab

所有删除操作（手动 + AI）一律走**软删除**进入回收站，与业务表隔离，不污染读路径。

| 操作 | 说明 |
|------|------|
| **恢复** | 把记录原样塞回业务表，关联引用自动恢复有效（uid 机制保证不冲突） |
| **彻底删除** | 物理删除（仅用户手动，二次确认） |
| **清空回收站** | 一键清空所有回收站记录（二次确认） |

#### 自动清理（v1.0.6 起）

回收站保留 **90 天**（`TRASH_RETENTION_DAYS`），超期自动物理清理：

- 触发时机：应用启动（数据加载后）+ 打开回收站 Tab 时
- 幂等：每天最多执行一次（localStorage 记录上次清理时间）
- 关联处理：清理时关联的未回滚 delete 类 AI 操作标记 `autoPurged`，操作历史显示「已自动清理」灰标，不提供回滚按钮
- 用户提示：自动清理时 toast「已自动清理 N 条超过 90 天的回收站记录」

> **隔离原则**：AI 无任何回收站操作能力（不暴露 restore/purge 接口），回收站管理仅由用户手动操作。

## 11. 全局搜索与命令面板

v1.0.9 起加入的 **⌘K 命令面板**，是工作台的全局入口，既能六源搜索业务数据直达详情，也能直接把问题抛给 AI 助手。

| 按键 | 动作 |
|------|------|

### 11.4 与 AI 联动

- 选中条目按 `Tab` → AI 助手自动打开，问题预设为「请分析这条数据：xxx」，并把该条目作为附加上下文注入
- 输入框无结果时按 `Enter` → 直接问 AI
- 输入 `?` 开头 → 强制问 AI

## 13. AI 助手

AI 助手是工作台的可选增强模块，不影响离线核心功能。**默认所有核心功能（订单/报价/结算/发票/数据等）都可在无 API Key、无网络时正常使用**；启用 AI 后，可用自然语言分析经营数据、起草写入操作、查询系统帮助、检索本地知识库。

### 13.1 概述与入口

**运行模式**：自动识别

| 模式 | 识别条件 | API Key 存储 |
|------|---------|-------------|
| **桌面版（Tauri）** | 检测到 `window.__TAURI__` | 应用数据目录的 `deepseek_token` 文件（不进 localStorage） |
| **浏览器版（含 file://）** | 其他 | localStorage 键 `wb_fastener_ai_key`（仅本机可见） |

**入口**：

- 顶栏闪电图标
- 快捷键 `⌥ + I`（打开/关闭）
- 命令面板（⌘K）的 `Tab` / `?` 前缀 / 无结果回车 → 自动打开 AI 并发送

**状态指示**：顶栏闪电图标颜色——绿色「● 直连就绪」/「● 桌面就绪」表示已配置；黄色「● 未设置 API_KEY」表示需先配置。

### 13.2 AI 设置（多模型接入）

点击 AI 助手顶栏「设置」按钮打开设置弹窗，包含以下配置项：

| 配置项 | 说明 |
|--------|------|
| **运行模式** | 显示当前是桌面版还是浏览器版，以及 API Key 存储位置 |
| **AI 状态** | 当前是否就绪、端点显示名 |
| **知识库（本地 RAG）** | 内嵌的知识库状态与操作区（与数据管理页同步） |
| **端点预设** | 一键按钮，自动填入下方 Base URL 与模型 |
| **Base URL** | OpenAI 兼容端点，需以 `/v1` 结尾 |
| **模型** | OpenAI 兼容模型名（不强制限制，自定义端点可填该端点支持的任意模型） |
| **API_KEY** | 编辑态回显真实 Key；留空保存则删除 |

#### 端点预设（v1.0.9 起）

| 预设 | Base URL | 默认模型 |
|------|---------|---------|
| **DeepSeek** | `https://api.deepseek.com/v1` | `deepseek-v4-flash` |
| **OpenAI** | `https://api.openai.com/v1` | `gpt-4o-mini` |
| **通义千问** | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| **本地 Ollama** | `http://127.0.0.1:11434/v1` | `qwen2.5` |
| **本地 oMLX** | `http://127.0.0.1:8000/v1` | `qwen2.5` |

- 预置推荐模型：`deepseek-v4-flash`（默认）/ `deepseek-v4-pro` / `gpt-4o-mini` / `gpt-4o` / `qwen-plus` / `glm-4-flash` / `llama3` / `qwen2.5`
- 端点显示名按 baseUrl 域名自动识别：DeepSeek / OpenAI / 通义 / 智谱 / 本地模型 / 自定义

#### 本地模型认证适配

- **Ollama**：本地端点无 Key 时发送占位 `Bearer ollama`（其 OpenAI 兼容层要求 Authorization 头非空，空值 401）。**API_KEY 可留空**。
- **oMLX**：**已保存的真实 Key 优先**（oMLX 校验 Key 与自身配置逐字一致，占位会被拒「Invalid API key」）。需在 oMLX「设置 → Auth & Info」配置后，在应用内填写相同值。

### 13.3 对话流程与持久化

#### 发送消息

1. 在 AI 抽屉底部输入框输入消息
2. 按 `Enter` 发送（或点击「发送」按钮）
3. **首次发送**会弹出**脱敏数据快照确认弹窗**，确认后记住（localStorage `wb_fastener_ai_confirm`），后续发送不再重复弹
4. 流式输出回复，期间「发送」按钮变为「停止」，可随时中止

#### 脱敏快照

每次发送前，系统自动构建脱敏数据快照注入 system prompt：

- **经营概况**：订单总数、销售额、采购成本、利润、毛利率、应收未收、应付未付、客户/供应商数
- **当前页面上下文**：根据当前所在视图（订单详情、订单列表、关联单位、签约报价等）自动注入对应数据
- **关键词命中实体**：消息中提及「催款/应收」「供应商/比价」「利润」等关键词时，自动注入相关排行与数据；命中单位名时注入该单位基本信息
- **不含**：联系人电话、地址、税号、银行账户等敏感字段（除非用户在对话中主动提供）

> 每条用户消息下方可点击「查看发送内容」展开本次发送的完整快照原文。

#### 流式增量落盘（v1.0.11 修复）

助手消息采用「**创建即入库 + 流式增量防抖落盘**」策略：

- 发送瞬间即创建带 id 的助手消息对象推入 `DB.aiChats`，随流式 chunk 更新内容并 `saveDBDebounced(800)` 增量落盘
- **关闭弹窗后台请求照常完成并已入库**：重开弹窗即可看到完整回复
- **中途退出应用**最多丢最后 <1s 的增量内容（`pagehide` 兜底再刷盘一次）
- 「停止」/出错不再整段丢弃：保留已生成部分，仅在末尾追加「已停止生成，以上为已生成部分」或「请求失败：...」说明
- 进行中的消息不可删除（删除按钮对 `pending` 消息隐藏）
- 回复生成期间重复发送给出明确 toast 提示「AI 正在生成回复，请稍候…」

#### 对话历史管理

- 历史保存最近 50 条（FIFO）
- 顶部「清空」按钮 → 清空全部对话历史
- 每条消息右下角「删除」按钮 → 删除单条记录
- 加载时自动清理上次会话流式中断残留的 `pending` 标记，避免重开后永久光标闪烁

#### 上下文自动压缩

历史携带量 6 → 20 条；总字符超 20000 时触发一次 AI 摘要压缩（`[system + 摘要 + 当前问题]`），失败降级不阻塞。压缩请求自身不走工具循环，不会递归触发。

#### 错误处理（v1.0.5 起）

错误分类器 `_friendlyError` 把底层异常转换为对用户友好的中文提示：

| 异常类型 | 转换结果 |
|---------|---------|
| AbortError（用户主动中止） | 透传，保留已生成部分 |
| `Failed to fetch` / `NetworkError` / `loadfailed` | 「网络连接失败，请检查网络后重试」 |
| 含 `tauri` / `invoke` / `非 Tauri 运行时` | 「AI 服务调用异常：...」 |
| 含 `stream` / `sse` / `eventsource` | 「AI 响应流中断，请重试」 |
| HTTP 4xx/5xx | 原始响应附在错误信息中（不再出现「请求失败：undefined」） |

### 13.4 常用提问与脱敏快照

冷启动（无对话历史）时显示**单行横向滚动 chips** 的常用提问区，一旦有对话记录即隐藏（清空对话后恢复）：

| 提问 | 用途 |
|------|------|
| 经营总结 | 本月销售额、利润、回款率、客户活跃度和待办 |
| 催款建议 | 按紧急程度排序的催款优先级 |
| 比价分析 | 各规格性价比最高的供应商 |
| 客户分析 | 交易频次、累计金额和毛利率的客户分级 |
| 话术生成 | 催款微信消息（友好但坚定） |
| 利润分析 | 最赚钱和最不赚钱的订单 |
| 任意提问 | 清空预设，自由输入 |

### 13.5 AI 工具调用（Function Calling）

v1.0.2 起接入 DeepSeek function calling 协议（OpenAI 兼容），AI 从「只读问答」升级为「可起草写入操作」，经用户逐条确认后落库。

#### 设计原则

1. **AI 只产出参数**，不直接执行；执行器复用项目现有校验规则与 `saveDB()` 链路
2. **写入类工具生成提案**，前端要求用户逐条确认，不会自动执行
3. **所有写入均记 aiOps 可回滚**（操作历史可追溯，支持单条/整批回滚）
4. **删除走软删除**进入回收站，AI 无彻底删除能力，无任何回收站操作能力

#### 三层分流（v1.0.5 完善）

`aiWriteLoop` 按工具类型分流为三路：

| 工具类别 | 副作用 | 确认 | 审计 | 回滚 |
|---------|--------|:---:|:---:|:---:|
| **查询类**（query_*） | 无 | 自动执行 | 不记 | — |
| **功能层**：navigate_view / open_*_drawer / open_*_form | 无（纯 UI） | 自动执行 | 不记 | — |
| **功能层**：export_order_excel | 有（生成文件） | 自动执行 | ✅ 记 `op:'export'` | 不可回滚 |
| **写入/删除/流转** | 有（改数据） | ✅ 确认弹窗 | ✅ 记 aiOps | ✅ 可回滚 |

#### 工具清单

完整 43 个工具按类别：

**A. 帮助类**（自动执行）
- `query_help` — 检索系统操作说明（用户问「怎么操作/如何使用」时优先调用）

**B. 查询类**（自动执行，无副作用）
- `query_units` / `query_specs` / `query_bom` / `query_prices` / `query_orders` / `query_settlements` / `query_invoices`

**C. 写入类**（生成提案，需用户确认）

| 类别 | 工具 |
|------|------|
| 关联单位 | `create_unit` / `update_unit` |
| 报价 | `create_price` / `update_price` |
| BOM | `create_bom` / `update_bom` |
| 属性 | `set_spec_value`（幂等，已存在跳过） |
| 订单 | `create_order` / `update_order_meta` / `add_order_item` / `update_order_item` / `remove_order_item` |
| 寻货 | `assign_supplier`（价格库匹配）/ `add_manual_supplier`（手动录入，自动建单位+写价格库）/ `remove_sourcing_option` |
| 结算 | `create_settlement` / `update_settlement` |
| 发票 | `create_invoice` / `update_invoice` |

**D. 删除类**（生成提案，走软删除进回收站，需用户确认）
- `delete_unit` / `delete_bom` / `delete_price` / `delete_order` / `delete_spec_value` / `delete_settlement` / `delete_invoice` / `remove_order_item`

**E. 流转类**（生成提案，需用户确认，状态机守则强制拒绝跳站）
- `flow_order_status` — 守 `NEXT_STATUS` 状态机：待确认 → 寻货中 → 报价中 → 签约完成 → 送货中 → 完成；可分支至「未成交」（可恢复）/「异常」/「取消」（终态）

**F. 功能层**（自动执行，不打断对话流）
- `navigate_view` — 跳转到 dashboard/units/specs/bom/prices/orders/settlements/invoices/data 及细分视图 settle-receipt/settle-payment/inv-issue/inv-receive；viewName=orders 且提供 orderId 时导航到订单详情
- `export_order_excel` — 触发浏览器下载，按订单状态自动选择导出模板（**记审计，不可回滚**）
- `open_settlement_drawer` — 调用 `openSettleDetail(unitId, tabType)`，tabType 支持 receipt/payment
- `open_invoice_drawer` — 调用 `openInvEdit(invoiceId)` 进入发票编辑
- `open_unit_form` / `open_order_form` / `open_price_form` / `open_bom_form` — 手把手引导新建业务表单

#### 系统操作指引

AI 的 system prompt 内置九大模块的操作要点（A-I），用户询问「怎么操作/怎么做/如何使用/在哪/能不能」时：
1. 先调用 `query_help` 检索完整帮助知识库
2. 能直接代做的（导航 / 导出 / 打开表单 / 打开抽屉）同时调用对应功能层工具
3. 无法代做的给出简明步骤

### 13.6 操作提案确认与撤销回滚

#### 操作提案确认弹窗

写入类工具触发时，弹出确认弹窗：

- **每条提案卡片**：类型徽章 + 目标摘要（如「新增单位：xxx」「订单流转：PO260811-001 → 签约完成」）+ 字段级 diff 预览（旧值 → 新值）
- **复选框**：默认全选有效提案；校验失败的提案复选框置灰不可选
- **删除类提示**：「删除后进入回收站，可在数据管理页恢复」
- **实时计数**：「共 N 条操作提案，X 条已选」
- **取消按钮**：标记 cancelled，回填「用户取消了操作提案，请不要再次起草相同操作」给模型
- **执行按钮**：先关弹窗再返回（用户可立即看到执行过程与结果），单条失败不中断其他

#### 并发脏读检测（v1.0.5 起）

防止用户在确认弹窗期间数据被外部并发修改：

- 确认时为每条 op 注入 `__beforeFingerprint`（基于 `validation.preview.before` 的 JSON 字符串）
- 执行前重新调用 validator 拿当前 before，对比指纹，不一致返回「数据已被修改，请刷新后重试」
- 批量入口先做一次批量脏读检测，任一条不一致整批拒绝；通过后批量内顺序执行不再检测（防前序修改误报）

#### 撤销与回滚（v1.0.9 起）

- **消息下方「撤销本轮改动」按钮**：支持一轮多批次（逗号分隔批量撤销）；按 aiOps 审计反向回滚（创建→删除、修改→还原旧值、删除→恢复）
- **刷新不失效**：批次 ID 持久化在 aiOps，重开对话仍可撤销
- **不误伤手动操作**：仅回滚该批次内的 AI 操作，不影响用户之后的手动改动
- **数据管理 → 操作历史**：可查看全部 AI 操作记录，支持单条回滚与整批回滚

### 13.7 本地知识库（RAG）

v1.0.12 起加入的「目录即知识库」纯前端 RAG：绑定本机目录即完成知识库，提问时离线检索相关片段注入上下文，回答带源文件引用。

#### 双入口

- **数据管理 Tab** 下方的「知识库」区块
- **AI 设置弹窗**内的「知识库（本地 RAG）」区

两入口共享同一 KB 状态，任一入口操作即时同步。

#### 绑定与解析

1. 点击「选择目录并索引」（仅 Chrome/Edge 支持目录选择 API）
2. 在文件选择窗口中选一个本地文件夹
3. 授权读取权限后，系统递归扫描（深度 ≤3）目录下所有受支持文件
4. 解析结果写入独立 IndexedDB 库 `wb_fastener_kb`（与业务库隔离）
5. **源文件不动**，仅在独立库存目录句柄、文件清单、分块全文与索引

#### 支持格式

| 格式 | 解析方式 | 备注 |
|------|---------|------|
| **md** | 直读（剥 BOM），追踪标题章节 | 标题 → chapter 字段 |
| **txt** | 直读（剥 BOM） | — |
| **PDF** | pdf.js 提文本层 | 逐页收集 → 按行映射页码 → 块记录块首行页码 |
| **docx** | mammoth 提纯文本 | — |

> 单文件超 200 万字符自动跳过。PDF/Word 需联网首次加载解析内核（pdfjs-dist / mammoth 已 npm 依赖打包进 iife bundle，由 `window.__KB_DEPS` 桥接，**不再走 CDN 动态加载**）。

#### PDF worker 双通道（v1.0.13 修复）

- **真环境**（http/https）：使用独立 worker 加速（`?url` 外置 asset）
- **file:// 双击运行**：浏览器禁止 `new Worker()`，由全局钩子 `globalThis.pdfjsWorker` 提供主线程 fake worker 兜底——**该钩子不可移除，否则 file:// 下 PDF 解析必败**

#### 本地 BM25 检索（不联网，不消耗 token）

- 中文 bi-gram + 英文单词分词，纯前端计算
- 相关度阈值过滤后再取 Top-N（默认 4，可选 3/4/5），低分弱命中不注入省 token
- v1.0.13 修正：分词不再去重，真实 tf 与文档长度参与打分

#### 定时增量更新（v1.0.13 起）

- 绑定成功 / 启动恢复后自动开启每 5 分钟静默扫描（仅页面可见时）
- 比对 `lastModified + size`，未变化的文件复用旧分块不重读盘，新增/变更/删除自动同步进索引
- 提问发送前距离上次索引超时则后台触发一次增量更新（不阻塞本次回答）
- 断开目录停止定时器

#### 检索注入与引用

提问时，若已绑定且开启检索，系统自动：

1. 取 Top-N 片段拼入 system prompt 的【知识库参考】区（含文件名/章节/页码标注）
2. AI 回答时若引用具体内容，在句末标注【依据：文件名】
3. **回答中的【依据：文件名】渲染为可点击按钮**，点击弹窗展示该文件的全部分块原文（含章节/页码标注），便于核对来源

#### 设置项

| 设置 | 说明 |
|------|------|
| **提问时检索知识库** | 开关；关闭后提问不注入知识库片段 |
| **注入 Top-N** | 3/4/5 片段可选 |
| **回答标注来源** | 开关；关闭后回答不带【依据：文件名】标注 |

#### 索引结果提示

索引完成 toast 显示：扫描到的受支持文件数、成功数、分块数与失败文件名明细（前 2 条）；扫到 0 个受支持文件时明确提示检查所选目录。目录读取权限异常不再静默吞掉。

## 14. 桌面版自动更新

v1.0.14 起新增桌面版自动更新（仅 Tauri 桌面端生效，web/file:// 静默跳过）。

### 14.1 检查机制

- **冷启动延迟 5 秒静默检查** GitHub Releases 的 `latest.json`（避开启动关键路径）
- 比对版本号，发现新版本后按「自动下载安装」开关决定后续流程
- 默认开关为开（localStorage `fw_auto_update`，`'1'` 为开）

### 14.2 更新流程

1. **检查版本**：拉取 `latest.json`，对比当前 `__APP_VERSION__`
2. **发现新版本**：toast「发现新版本 vX.X.X」（静默检查时不弹 toast）
3. **后台下载**（不阻塞使用）：实时进度（0% → 99% → 100%）
4. **下载完成**：toast「更新已就绪，重启应用后生效」+ 确认弹窗「立即重启 / 稍后」
5. **重启应用**：调用 `process.relaunch()`，当前数据已自动落盘
6. **签名校验**：Tauri updater 以 `tauri.conf.json` 内嵌公钥 + `.sig` 签名验证，未通过则拒绝安装

### 14.3 版本号单一来源

版本号以 `package.json` 的 `version` 字段为单一来源，构建时由 Vite `define` 注入全局 `__APP_VERSION__`，并同步至 `src-tauri/tauri.conf.json`。

## 15. 常见问题

### Q：数据会丢失吗？

不会。IndexedDB 是浏览器本地持久存储，正常使用不会丢失。建议绑定本地文件同步（数据管理页），双重保障。定期导出 JSON 备份也是好习惯。桌面版还可在数据管理页开启「自动快照」按 N 天间隔自动备份到 `backups/` 子目录。

### Q：换电脑怎么迁移数据？

1. 在旧电脑上「导出 JSON 备份」
2. 将 JSON 文件拷贝到新电脑
3. 在新电脑上打开工作台 → 「数据管理」→「导入 JSON 恢复」

> 导出/导入均**不含回收站与操作历史**（用户明确约束），迁移后回收站与 AI 操作记录为空。

### Q：搜索框怎么用？

直接输入关键词回车即可，支持模糊匹配。点击输入框右侧的 × 清除搜索（不在输入时实时触发，避免中文输入法冲突）。

### Q：下拉框里没有我想要的值怎么办？

所有下拉框都支持手动输入：直接在输入框中打字，按回车即可创建新值并自动同步到规格管理枚举值中。

### Q：手动录入供应商后会自动保存吗？

会。在寻货弹窗中手动录入供应商时，系统自动完成三件事：
1. 新供应商 → 自动创建关联单位（角色=供应商，评级=新客）
2. 自动将报价写入价格库
3. 添加到当前产品的供应商分配列表

下次对相同规格寻货时，该供应商会出现在价格库匹配列表中。

### Q：一个产品可以分配多个供应商吗？

可以。例如需求 5000 个 M10 螺栓，可以分配给供应商 A 3000 个 + 供应商 B 2000 个。系统自动汇总分配总量，显示寻源状态和进度条。

### Q：不小心关掉了页面，填了一半的表单怎么办？

表单草稿自动保存。重新打开后点击「新建」，会弹窗提示恢复草稿（选「恢复草稿」）或放弃（选「放弃草稿」）。

### Q：手机上可以用吗？

可以。工作台适配手机浏览器，侧边栏变为汉堡菜单。推荐在手机浏览器中打开后「添加到主屏幕」，像 APP 一样使用。

### Q：文件同步显示「待授权」怎么办？

刷新页面后浏览器需要重新确认文件访问权限。进入「数据管理」页，点击「重新授权连接」并在弹窗中确认即可。

### Q：BOM 和价格管理有什么关系？

BOM 是标准产品目录，价格管理是供应商报价库。同一个 BOM 产品可以在多个供应商处有不同的报价（不同的采购单价）。采购订单添加产品时可从 BOM 选择，系统自动引用价格库中对应供应商的报价计算利润。

### Q：结算管理和发票管理是什么关系？

结算管理记录实际收付款，发票管理自动从结算记录生成开票/收票任务。每新增一笔结算，发票管理自动新增一条对应任务，无需手动录入开票信息。两者相互独立维护。

### Q：发票企业抬头信息从哪里来？

在「关联单位」中每个单位可维护「开票信息」字段（税号、地址、电话、开户行、账号）。在发票管理中开票时，系统自动从该采购商单位的开票信息填充到企业抬头输入框中。

### Q：AI 助手必须配置才能用吗？

不必须。AI 助手是可选增强模块，**默认所有核心功能（订单/报价/结算/发票/数据等）都可在无 API Key、无网络时正常使用**。需要使用 AI 时，在 AI 设置中填入 API Key 即可。本地 Ollama 端点可免 Key 使用。

### Q：浏览器版和桌面版的 AI 有什么区别？

| 项目 | 浏览器版 | 桌面版 |
|------|---------|--------|
| API Key 存储 | localStorage（键 `wb_fastener_ai_key`） | 应用数据目录的 `deepseek_token` 文件 |
| 调用方式 | 前端直连（CORS 已放行，含 file:// 的 null origin） | Tauri Rust 命令代理 |
| 工具调用（Function Calling） | 完整支持 | Rust 侧已透传 tool_calls delta，桌面版与浏览器版行为一致 |
| 离线使用 | 仅本地 Ollama/oMLX 端点可用 | 仅本地 Ollama/oMLX 端点可用 |

### Q：AI 写入操作会自动执行吗？

不会。**写入类工具调用只生成「提案」**，前端要求用户逐条确认后才执行。查询类（query_*）和功能层（navigate_view 等）工具会立即执行，不需要用户确认。

### Q：AI 操作能撤销吗？

能。每轮 AI 写入操作完成后，消息下方有「撤销本轮改动」按钮，按 aiOps 审计反向回滚（创建→删除、修改→还原旧值、删除→恢复），刷新不失效，不误伤手动操作。也可在「数据管理 → 操作历史」Tab 单条或整批回滚。

### Q：删除的数据去哪了？

所有删除操作（手动 + AI）一律走**软删除**进入回收站。可在「数据管理 → 回收站」Tab 恢复或彻底删除。回收站保留 90 天，超期自动物理清理（清理时关联的未回滚 delete 类 AI 操作标记 `autoPurged`，不可回滚）。

### Q：AI 能调用回收站吗？

不能。AI 无任何回收站操作能力（不暴露 restore/purge 接口），回收站管理仅由用户手动操作。

### Q：知识库支持哪些文件？怎么用？

支持 **md / txt / PDF / docx** 四种格式。在「数据管理」Tab 下方的「知识库」区块或 AI 设置弹窗内点击「选择目录并索引」绑定一个本地文件夹，系统自动解析并存储到独立的 `wb_fastener_kb` 库（与业务库隔离）。提问时若开启检索，系统会用本地 BM25 取 Top-N 片段注入 AI 上下文，回答带【依据：文件名】可点击查看原文。**全程不联网、不消耗 token**。

### Q：AI 对话历史会持久化吗？

会。助手消息采用「创建即入库 + 流式增量防抖落盘」，关闭弹窗后台请求照常完成并已入库，重开即可看到完整回复。最多保存最近 50 条。

### Q：命令面板（⌘K）能搜索什么？

六源搜索：订单 / 客户 / 报价 / BOM / 结算 / 发票，最多 40 条结果，关键字高亮。无结果时回车直接问 AI；输入 `?` 开头强制问 AI；选中条目按 `Tab` 把该条作为上下文问 AI。

### Q：快捷键在输入框里会失效吗？

`⌥` 系列快捷键在输入框内自动禁用，不干扰输入法。但 `⌘ + K`（搜索）和 `⌘ + S`（保存）在输入框内也能触发。AI 输入框的快捷键：`Enter` 直接发送、`⌘ / Ctrl + Enter` 或 `Shift + Enter` 换行。

### Q：本地模型（Ollama / oMLX）怎么接入？

在 AI 设置中选择对应预设（自动填入 Base URL 与模型），或手动自定义端点：

- **Ollama**：Base URL `http://127.0.0.1:11434/v1`，**API_KEY 可留空**（系统会发送占位 `Bearer ollama`）
- **oMLX**：Base URL `http://127.0.0.1:8000/v1`，**API_KEY 需与 oMLX「设置 → Auth & Info」中的值一致**（系统优先用已保存的真实 Key，占位会被拒）
